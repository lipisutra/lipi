# Какие отношения между договором и кодом стоит записывать

- Created: 2026-11-21
- Updated: 2026-11-21
- Status: closed
- Closed: 2026-11-21
- Result: Срез от правки договора описан в [ISS-023](../../issue/2026/iss-023-srez-po-diffu-ot-izmeneniya-dogovora.md). К ролям связей вернёмся после него.

## Вопрос

Какие сведения автор может один раз записать рядом с кодом, чтобы при следующем изменении договора ревьюеру не пришлось восстанавливать их по реализации?

## Принцип и критерии

Понятия и договоры называет проект. Lipi поддерживает небольшой закрытый набор отношений с одинаковым смыслом в разных проектах и репозиториях. Для каждого нового отношения, которое предстоит указывать вручную, нужны четыре ответа.

1. Знает ли автор это в момент правки, без отдельного разбора?
2. Какой смысл потеряется, если Lipi попытается вывести отношение из пути, слоя, истории Git или уже записанных ссылок?
3. На какой конкретный вопрос срез или проверка сможет ответить иначе?
4. Как будет видна неполнота, если отношение указано лишь у части известных мест?

## Направления

**1. Сначала — срез от изменения договора.** Сейчас [срез по диффу](../../../docs/ru/slice-diff.md#selection) пропускает Markdown. Если изменена только строка требования под явным якорем, предлагаем показать прежнюю и новую формулировки и связанные с разделом места в коде и тестах. Для этого достаточно диффа Git и существующих меток. Даже редакционная правка может дать такой срез. Нужно ли менять поведение, решает ревьюер.

**2. Затем — необязательные роли связей.** Например, функция `rebuild` читает выгрузку и составляет отчёт. Для договора строки выгрузки она потребитель (`consumes`), а для договора отчёта — производитель (`produces`). Фильтр по потребителям первого договора дал бы список мест, которые стоит открыть при перестановке полей. Роль принадлежит паре «место → цель» и сохраняет смысл через границу репозитория.

При частичной разметке полезен ответ «2 потребителя, ещё 3 связанных места без роли». Счёт охватывает только найденные связи в прочитанных источниках. При изменении кода [T2](../../../docs/ru/codes.md#t2) и [A4](../../../docs/ru/codes.md#a4) могут напомнить сверить локальную пару с разделом. Определить, продолжает ли функция читать формат, можно по коду. Для межрепозиторных связей эти сигналы сейчас не рассчитываются.

**3. Примеры проверки — в договоре, результаты запусков — у исполнителя проверки.** Автор записывает условие, действие и наблюдаемый результат, как в [практикуме](../../../docs/ru/first-task.md#review). Такой пример уже можно прочитать в срезе раздела рядом с местами в тестах. Факт прохождения на конкретной версии хранит инструмент, который запускал проверку. Отдельный журнал прогонов в Lipi для этого не нужен.
