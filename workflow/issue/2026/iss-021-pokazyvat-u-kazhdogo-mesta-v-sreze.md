# Показывать у каждого места в срезе по диффу, какие метки его связывают с изменением

- Created: 2026-11-20
- Updated: 2026-11-20
- Status: open
- Kind: request

## Observation

В текстовом [срезе по диффу](../../../docs/ru/slice-diff.md#response) видны
затронутые понятия и связанные места. Когда понятий несколько, ревьюеру
пришлось открыть ещё два среза, чтобы выяснить, по какой метке найдено
каждое место. В JSON 1.1.0 у точек входа и мест в коде поле
`via` содержит только первую совпавшую цель. У мест в тестах этого поля нет.

## How to reproduce or where it occurred

У участка кода, формирующего ответ, есть метки на два раздела:
`#read-record` и `#summary`. Читатель ответа размечен первым якорем,
экран и тест сводки — вторым. Изменить участок и выполнить
`lipi slice --diff HEAD`. Все три места перечислены вместе.

## Compatibility and release

Целевой выпуск — 1.2.0: новое поле JSON и подпись в тексте расширяют возможности среза.
На опубликованном `v1.1.0` (`8a34a0b`) у места с целями `docs/api.md#summary`
и `docs/api.md#read-record`, указанными именно в таком порядке, оба режима
вернули `"via": "docs/api.md#read-record"` в блоках `entry` и `code`.
В блоке `tests` поля `via` не было. Эти значения зафиксированы как литералы
в тесте совместимости `tests/test_slice_diff.py` для проверки и после реализации.

## Acceptance criteria

- Область изменения — `lipi slice --diff` и `--staged`. Обычные срезы по
  странице, разделу, работе и файлу сохраняют свой вывод.
- Если дифф затронул несколько разных целей, текст подписывает каждое место
  в блоках `entry`, `code` и `tests`. В примере у читателя видно «через
  #read-record», у экрана и теста — «через #summary». Место с двумя
  совпавшими целями выводится один раз с обеими. При одной цели подпись опускается.
- Короткая форма `#якорь` применяется, если среди всех целей диффа этот
  якорь обозначает одну цель. Повторы той же цели у разных мест не учитываются.
  При коллизии указываются полные адреса: `путь#якорь` у локальной цели,
  `repo::путь#якорь` у внешней. Для целей без якоря выводится их адрес.
  Сокращение определяется до фильтров и обрезки вывода.
- В JSON схемы 1 у каждого места в этих трёх блоках добавляется
  `matched_targets` — список всех различных целей, общих для меток места и
  диффа, даже когда совпадение одно. Значения — канонические строки, включая
  префикс подключения для внешних целей, в лексикографическом порядке полного
  адреса. Например: `["docs/api.md#read-record", "docs/api.md#summary"]`.
  Существующая строка `via` в `entry` и `code` равна `matched_targets[0]`,
  как при нынешнем выборе первой цели. У `tests` добавляется только
  `matched_targets`. Поле `via` в других видах среза сохраняет свой смысл.
- Закрепить пример в справке и проверить текст и JSON в обоих режимах:
  одна цель, две у одного места, одинаковый якорь у разных страниц и репозиториев.
