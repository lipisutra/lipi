# Поиск находит страницы из отключённой workflow/

- Created: 2026-11-25
- Updated: 2026-11-25
- Status: open
- Kind: friction

## Observation

В Lipi 1.4.0 локальный поиск охватывает весь Markdown проекта. Поэтому
при отключённых рабочих материалах (`"workflow": null`) и поиск по
заголовкам, и `lipi slice --search` находят страницы из `workflow/`.
В таком проекте эта папка принадлежит самому проекту: там могут лежать
его собственные планы, отчёты и мастер-план в своём формате.

На живом проекте собственный мастер-план из `workflow/` попал в первую
пятёрку кандидатов `--search` по вопросу о сроке хранения и вытеснил
разделы описания.

У соседа поиск ограничен областью чтения подключения: описанием,
решениями и `page_dirs`. Локальный поиск такого ограничения не имеет.

## How to reproduce or where it occurred

В проекте с `{"docs": "docs", "workflow": null}`:

- `docs/retention.md` со строкой «Квитанция хранится 30 дней»;
- `workflow/plan.md` с заголовком «Unique roadmap» и строкой
  «Квитанция хранится в журнале проекта».

`lipi slice --search 'квитанция журнале'` выводит первым `workflow/plan.md`.
`lipi slice 'Unique roadmap'` находит ту же страницу по заголовку.

## Acceptance criteria

- Решить, какую область охватывает локальный поиск при `"workflow": null`:
  весь Markdown проекта или только описание и решения, как у соседа.
  Записать решение в описании среза на двух языках.
- Если область сужается, то одинаково для поиска по заголовкам
  и для `--search`. Явный путь к странице из `workflow/` по-прежнему
  открывается срезом.
- При включённых рабочих материалах поиск по ним работает, как в 1.4.0.
