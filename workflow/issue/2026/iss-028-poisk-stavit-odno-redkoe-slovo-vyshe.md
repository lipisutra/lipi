# Поиск ставит одно редкое слово выше нескольких совпавших

- Created: 2026-11-25
- Updated: 2026-11-26
- Status: closed
- Closed: 2026-11-26
- Result: В тестовых примерах на русском и английском поиск первым возвращает абзац о хранении квитанции. В запросе о недоступном API первым остаётся документ с термином API.
- Kind: bug

## Observation

В Lipi 1.4.0 `lipi slice --search` ставит выше страницу, где совпало одно
редкое слово, чем страницу, где совпали несколько слов вопроса. Так бывает
со вспомогательными словами вопроса, например «сколько» или «когда»: в
описании они могут встречаться реже, чем термины. Частотный вес такого
слова оказывается больше суммы весов терминов.

На живом проекте запрос «сколько хранится квитанция» вывел первыми пять
страниц, где совпало только «сколько». Нужный раздел, где совпали
«квитанция» и «хранится», в первую пятёрку не попал. Запрос без
вопросительного слова нашёл его первым.

## How to reproduce or where it occurred

В проекте с `"docs": "docs"`:

- шесть страниц со строкой «Квитанция выдаётся после применения»;
- `docs/retention.md` с разделом `#receipts` и строкой «Квитанция хранится 30 дней»;
- `docs/copy.md` со строкой «Копия хранится до очистки»;
- `docs/pack.md` со строкой «Сколько единиц входит в пакет».

Запрос `lipi slice --search 'сколько хранится квитанция'` ставит первым
`docs/pack.md`, а `docs/retention.md#receipts` — вторым. Без `docs/copy.md`
порядок верный: слово «хранится» тогда встречается один раз и весит
столько же, сколько «сколько».

## Acceptance criteria

Оба результата должны выполняться одновременно, на русском и английском:

- в примере выше `docs/retention.md#receipts` идёт выше `docs/pack.md`;
- для запроса «что если API недоступен» страница с `API` остаётся выше
  страниц, где совпали только «что» и «если», как в существующем тесте
  `tests/test_search_match.py`.

Формула ранжирования выбирается при реализации. Правило «сначала число
совпавших слов» не подходит: оно поднимет страницу с «что» и «если» выше
страницы с одним `API` и нарушит второй результат.

## Граница

Исправление касается порядка кандидатов, когда слова читателя уже есть
в документах. Оно не решает поиск по перефразированному вопросу, где слова
читателя не совпадают со словами раздела. В замере на 1.4.0 один и тот же
раздел по прямой формулировке вышел первым, а по перефразированной — 322-м;
уменьшение веса редких слов опустило его до 366-го места. Для таких вопросов
есть отдельная гипотеза: использовать текст ссылок как дополнительную
формулировку раздела, на который они ведут.
