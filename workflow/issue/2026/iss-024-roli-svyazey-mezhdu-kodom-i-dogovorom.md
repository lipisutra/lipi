# Роли связей между кодом и договором

- Created: 2026-11-21
- Updated: 2026-11-21
- Status: open
- Kind: request

## Observation

После правки формата строки срез показывает все связанные места. Чтобы выбрать, каких читателей проверить, ревьюеру приходится открыть также код записи. Автор при разметке уже знает, какое место формирует строку и какое её потребляет. В [DSC-002](../../discussion/2026/dsc-002-kakie-otnosheniya-mezhdu-dogovorom-i-kodom.md) предложены две необязательные роли для связи места с конкретной целью.

## How to reproduce or where it occurred

В небольшом проекте `write_row` пишет строку выгрузки, `rebuild` читает её и составляет отчёт, а `show_summary` выводит отчёт. Все три функции находятся в одном слое. На обычных метках проверены два среза.

| Команда | Найденные функции |
| --- | --- |
| `lipi slice docs/export.md#row --only code` | `rebuild`, `write_row` |
| `lipi slice docs/report.md#summary --only code` | `rebuild`, `show_summary` |

Для строки выгрузки у `rebuild` роль `consumes`, для отчёта — `produces`. При перестановке полей выгрузки выбор её потребителей должен привести к `rebuild`. При изменении требований к формированию отчёта та же функция нужна уже по второй связи.

## Acceptance criteria

Предложение для согласования.

- После целей метки можно через пробел указать `role=consumes`, `role=produces` или обе роли через запятую. Например, `@trace docs/export.md#row role=consumes,produces` подходит для функции, которая читает, нормализует и записывает строку того же формата. В общем срезе у одного адреса видны обе роли. По каждому из фильтров `--role consumes` и `--role produces` функция находится один раз.
- Если в одной метке перечислены несколько целей, все указанные роли относятся к каждой цели. У `rebuild` роли различаются, поэтому перед объявлением стоят две соседние метки.

  ```python
  # @trace docs/export.md#row role=consumes
  # @trace docs/report.md#summary role=produces
  def rebuild(row):
      return make_summary(parse_row(row))
  ```

  При правке обоих договоров `lipi slice --diff HEAD` показывает `rebuild` один раз и в тексте, и в JSON. У этого места две связи с указанными выше ролями. В сводке функция учтена один раз.
- Если соседние метки одной группы указывают на одну цель, их роли объединяются без повторов и независимо от порядка строк. Например, обычная метка на `#row` рядом с меткой `role=consumes` на тот же якорь даёт одну связь с ролью `consumes`. Если добавить к группе метку `role=produces` на `#row`, у той же связи будут обе роли. В обоих случаях счётчик мест без роли равен нулю для этого примера. Связь остаётся без роли, если все метки группы на эту цель корректны и ни в одной из них роль не указана.
- При неизвестном значении, например `role=reads` или `role=consume`, `lipi check` выдаёт ошибку на строке метки и называет неверное значение. Это относится и к списку `role=consumes,reads`. Обычный срез проекта без ролевой разметки сохраняет привычный вид.
- Для роли требуется явный якорь Markdown в метке кода. `lipi check` выдаёт ошибку для `@trace ADR-007 role=consumes`, для роли на номере другой работы (например, `PLN-003`) и для роли на тестовой метке. Метка на `ADR-007` без роли допустима. Если договор описан в разделе решения, роль можно указать у пути к этому файлу с явным якорем.
- Для примера с `rebuild` срез файла показывает, какой договор функция читает и какой формирует. При изменении только `#row` команды `--diff` и `--staged` показывают роль для `#row`. При запросе страницы с двумя затронутыми целями подпись различает роль для каждой. Если функция потребляет A и связана с B без роли, обе связи видны в одной строке.
- Точки входа остаются в `entry`, остальные места кода — в `code`. При выборе роли каждый из этих блоков показывает подходящие места и адреса мест с неизвестной ролью. Тесты остаются в `tests` и исключены из ролевого подсчёта.
- Если после `--layer` найден один потребитель и ещё три места только с неизвестной ролью, сводка сообщает «1 потребитель, ещё 3 места без роли». Общая сумма считает каждое место один раз, включая точки входа. Счёт ведётся до `--only` и обрезки, только в прочитанных источниках. У подключённого соседа адрес включает имя подключения. Фильтр по роли сохраняет охват проверки устаревания.
- Текст и JSON показывают одни и те же адреса в пределах [общего бюджета](../../../docs/ru/slice-output.md#budget), с числом пропусков. В JSON `target_roles` передаёт роли по целям и в обычном срезе, и в срезе по изменению. Поле `reasons` объясняет, почему место попало в [срез по диффу](../../../docs/ru/slice-diff.md#json). Ключ `--full` раскрывает выдержки.

## Границы предложения

Роль указывает, как код использует конкретный договор. В работе по номеру фиксируется задача, в тесте — проверка поведения. Для решения по номеру пока достаточно существующей связи «код следует ADR». Если в решении описан формат, для него подходит якорь раздела. К ролям для ADR целиком и к ролям в карте стоит вернуться, когда появится конкретный вопрос ревьюера, на который они помогут ответить.
