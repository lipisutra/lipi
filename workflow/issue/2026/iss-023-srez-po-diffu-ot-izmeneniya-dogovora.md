# Срез по диффу от изменения договора

- Created: 2026-11-21
- Updated: 2026-11-21
- Status: closed
- Closed: 2026-11-21
- Result: Команды `lipi slice --diff` и `--staged` показывают обе стороны правки договора и связанные места в коде и тестах, в том числе ссылки на удалённые якоря.
- Kind: request

## Observation

[Срез по диффу](../../../docs/ru/slice-diff.md#selection) пропускает Markdown. Если автор изменил только требование, ревьюеру приходится отдельно открывать срез раздела, чтобы найти связанный код и тесты. После удаления якоря открыть срез по прежнему адресу уже нельзя. Запрос следует из [DSC-002](../../discussion/2026/dsc-002-kakie-otnosheniya-mezhdu-dogovorom-i-kodom.md).

## How to reproduce or where it occurred

В разделе `docs/export.md#row` задан порядок полей строки. На раздел ссылаются функция записи и тест чтения. Изменить только порядок полей в тексте и запустить `lipi slice --diff HEAD`. Нужны прежняя и новая формулировки и оба места для проверки. Подготовив ту же правку в Git, повторить с `lipi slice --staged`.

План реализации — [PLN-003](../../plan/2026/pln-003-srez-po-izmeneniyu-dogovora.md).

## Acceptance criteria

- В обоих режимах добавленные строки относятся к области явного якоря на новой стороне диффа, удалённые — на прежней. Границы те же, что у [A4](../../../docs/ru/codes.md#a4). Учитываются все Markdown-файлы, допустимые как цели меток, включая решения и рабочие документы, с обычными исключениями проекта. Заголовок без собственного якоря внутри размеченного раздела принадлежит этому разделу.
- Один срез показывает, что изменилось в договоре и какие места кода и тестов стоит открыть. При одновременной правке договора и кода место выводится один раз со всеми основаниями.
- В [JSON схемы 1](../../../docs/ru/slice-diff.md#json) различимы прежняя и новая формулировки и основания, по которым найдено каждое место: правка договора, ссылка по номеру решения или удалённая цель.
- Для прежней и новой формулировок действует общий [предел вывода среза](../../../docs/ru/slice-output.md#budget). По умолчанию текст и JSON показывают одинаковые выдержки и отмечают обрезку длинной правки. С `--full` обе формулировки доступны целиком.
- **Главный пример.** Заменить `#row` на `#record`, перевести метку функции на новый адрес и оставить тест на старом. Из одного среза видны удалённая и добавленная цели, исправленная связь функции и забытая метка теста. Из этих двух меток только последняя даёт T1 при проверке нового состояния. Для такого вывода достаточно двух сторон диффа, устанавливать факт переименования не требуется.
- При удалении якоря без замены срез показывает прежние места с пометкой «цель удалена». Связь, снятую в том же диффе, можно отличить от метки, которая всё ещё указывает на удалённую цель.
- При правке текста ADR срез отдельно показывает места «по номеру решения», например по `ADR-007`. Такая связь относится к решению целиком. Если одно место связано также с изменённым разделом по якорю, у него видны оба основания.
- Правка вне всех областей якорей даёт число непрерывных изменённых участков; замена абзаца считается один раз. Для изменённого раздела с якорем, у которого нет видимых связей, вывод другой: «В просмотренных источниках связанных мест не найдено». Это позволяет отличить отсутствие якоря от отсутствия найденных меток.
- Для соседей срез указывает просмотренные источники и границы чтения. Связанный код соседа виден при `code` в `read` у подключения владельца договора, тесты — при `tests`. Дифф относится к репозиторию запуска. Сведения о соседях отражают доступную версию каждого источника.
