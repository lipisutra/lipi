# Поиск по заголовкам в разрешённых каталогах подключённых репозиториев

- Created: 2026-11-20
- Updated: 2026-11-20
- Status: open
- Kind: request

## Observation

Разработчик знает слова из заголовка страницы, но может начать задачу
в другом репозитории. Одна и та же фраза там даёт «цель не найдена»,
а в репозитории-владельце сразу находит страницу по заголовку.

## Как воспроизвести или где встретилось

1. Подключить соседний репозиторий под именем `neighbor` с `read: ["docs"]`.
   В обоих проектах задать `"workflow": null`, каталог описания — `docs/`.
2. У соседа создать `notes/drafts/export.md` с заголовком
   «Повторная выгрузка отчёта». В исходном проекте такой страницы нет.
3. Выполнить `lipi slice 'выгрузка отчёта'` в каждом репозитории.
   В версии 1.0.1 у владельца находится обычная Markdown-страница
   (`kind: page`, `found: title`), в исходном проекте — `not-found`.

## Ожидаемый результат

После локального промаха Lipi предлагает явно запустить поиск той же фразы
у прямых подключений, для которых проект разрешил поиск по заголовкам.
Если разрешён только каталог `notes/drafts/`, поиск находит страницу
в нём и пропускает одноимённую страницу из `notes/private/`. Это работает
и при `workflow: null`. Достаточно существующего сравнения заголовков.

Совпадение показывает владельца, путь, заголовок и причину:
`neighbor::notes/drafts/export.md — Повторная выгрузка отчёта (по заголовку)`.
По этому адресу разработчик может открыть файл у владельца или выполнить там
`lipi slice notes/drafts/export.md`. Разрешение на поиск охватывает путь
и заголовок; для вывода содержимого действуют отдельные права чтения.
