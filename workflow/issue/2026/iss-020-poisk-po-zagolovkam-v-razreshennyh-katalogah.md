# Поиск по заголовкам в разрешённых каталогах подключённых репозиториев

- Created: 2026-11-20
- Updated: 2026-11-20
- Status: closed
- Closed: 2026-11-20
- Result: В Lipi 1.1.0 подсказка при локальном промахе ведёт к странице подключённого репозитория; результат подтверждён в пилоте из корня и из подкаталога.
- Kind: request

## Observation

Разработчик знает слова из заголовка страницы, но может начать задачу
в другом репозитории. Одна и та же фраза там даёт «цель не найдена»,
а в репозитории-владельце сразу находит страницу по заголовку.

План реализации — [PLN-002](../../plan/2026/pln-002-poisk-stranic-v-podklyuchennyh-repozitoriyah.md).

## How to reproduce or where it occurred

1. Из корня проекта-потребителя подключить `../neighbor` под именем
   `neighbor` с `read: ["docs"]`. В обоих проектах каталог описания — `docs/`.
   Задать `"workflow": null`: проекты ведут собственные карточки в Markdown,
   поэтому у них нет рабочих материалов Lipi и шапок его формата.
2. У соседа создать `notes/drafts/export.md` с заголовком
   «Повторная выгрузка отчёта». В исходном проекте такой страницы нет.
3. Выполнить `lipi slice 'выгрузка отчёта'` в каждом репозитории.
   В версии 1.0.1 у владельца находится обычная Markdown-страница
   (`kind: page`, `found: title`), в исходном проекте — `not-found`.

## Expected result

В `lipi.json` потребителя у подключения появляется необязательное поле
`page_dirs`. Оно перечисляет каталоги Markdown-страниц относительно корня
соседа и расширяет область `docs` во всех командах, читающих соседа.
Метка на явный якорь такой страницы проходит `check` и выводит страницу в `map`
по обычному правилу карты. Если `page_dirs` указан без `docs` в `read`, это C1. Например:

```json
{"repos":{"neighbor":{"path":"../neighbor","read":["docs"],"page_dirs":["notes/drafts"]}}}
```

В примере страницы из `notes/drafts/` доступны для поиска и чтения срезом
по обычным правилам, а `notes/private/` остаётся вне области.
Без `page_dirs` действует прежняя область чтения. Lipi 1.0.1 выдаёт C1
на конфигурацию с этим полем, поскольку ключ ему неизвестен.

Каждый элемент `page_dirs` — непустой относительный путь внутри корня
соседа. Неверный тип, абсолютный путь, выход за корень (включая переход
по символической ссылке) или два элемента с одним разрешённым путём дают C1.
Пересечение с каталогом описания и вложенность каталогов допустимы:
области объединяются, каждая цель участвует в поиске один раз.

Для поиска по заголовкам у соседа нужен его собственный `lipi.json`.
Без него доступны только явные цели вида `neighbor::путь.md#якорь`;
наличие `page_dirs` у потребителя этого правила не меняет.

Подсказка появляется только для локальной текстовой фразы с результатом
`not-found`. Для каждого доступного подключения с `docs` в `read` и своим
`lipi.json` Lipi выводит готовую команду в порядке ключей `repos`, например
`lipi slice 'neighbor::выгрузка отчёта'`. При `ambiguous` пользователь уже
получает местных кандидатов. Для явно названного соседа и при отсутствии
подходящих подключений подсказки тоже нет. При формировании подсказки
поиск у соседа не запускается: предложенная команда может дать `not-found`.
В JSON схемы 1 те же команды идут в необязательном массиве `suggestions`
с полями `repo` и `command`. Когда подсказок нет, поле отсутствует.

Поиск идёт только у названного соседа по [правилам среза](../../../docs/ru/slice.md):

- Одно совпадение по заголовку даёт срез и код выхода 0. В тексте видны
  владелец, заголовок, причина совпадения и открываемый путь к файлу.
- Несколько совпадений дают код 1, `error: ambiguous` и до пяти кандидатов
  в обычном порядке среза. При отсутствии совпадений — код 1 и `error: not-found`.

В JSON адрес цели и каждого кандидата задаётся полями `repo` и `target`.
Для найденной страницы это `"repo": "neighbor"` и
`"target": "notes/drafts/export.md"`. Адрес одинаков из любого каталога запуска.

## Acceptance criteria

Из корня потребителя разработчик вводит локальный запрос, следует подсказке
и открывает в редакторе путь из результата — `../neighbor/notes/drafts/export.md`.
Затем повторяет оба вызова из `src/`: путь из текстового ответа
`../../neighbor/notes/drafts/export.md` открывает тот же файл, а адрес в JSON
совпадает с полученным из корня.

Дополнительно проверить границы на том же проекте:

- Без `page_dirs` запрос `lipi slice 'neighbor::Отправка отчёта'` находит
  заголовок в `docs/guide.md#send` соседа (`found: title`, код 0). Затем
  добавить `"page_dirs": ["docs"]` и убедиться, что совпадение осталось одним.
- Убрать `lipi.json` соседа. Та же фраза даёт `not-found` (код 1), а точный
  `neighbor::docs/guide.md#send` по-прежнему открывается (код 0).
- Для двух подходящих подключений при локальном промахе видны две команды,
  даже если у одного соседа совпадений нет. При локальной неоднозначности
  видны только кандидаты.
