# V4 сообщает, какие управляемые правила обновит lipi init

- Created: 2026-11-20
- Updated: 2026-11-20
- Status: in progress
- Kind: request

## Observation

После обновления программы с 1.1.0 до 1.1.1 проект с прежними правилами
проходит `lipi check` без подсказки. Новые инструкции получает только тот,
кто прочитал CHANGELOG и запустил `lipi init` в этом проекте.

## How to reproduce or where it occurred

Развернуть проект с Lipi 1.1.0, установить 1.1.1 и в том же проекте
сравнить `lipi check` с `lipi init --dry-run`. План обновляет
`.agents/lipi/README.md` и `.agents/lipi/documentation.md`. После
применения правил повторная проверка должна проходить без V4.

## Acceptance criteria

- V4 — предупреждение в `lipi check`, настраиваемое через `codes`. При исправном
  lock с отпечатками сравнение выполняется в пределах одной мажорной версии,
  если версия установленной программы равна записанной в lock или новее.
  Сравнить `lock.files` с ожидаемыми путями и отпечатками из того же расчёта, что у
  [повторного init](../../../docs/ru/commands.md#update). Пропущенные выпуски
  ничего не меняют в сравнении. При совпадении отпечатков V4 молчит.
- В редактируемой установке (`pipx install --editable .`) изменить один
  управляемый шаблон, сохранив номер версии. Ожидается одна V4 с путём
  соответствующего файла проекта. Если версия программы ниже записанной
  в lock, о версии сообщает V1, а V4 молчит.
- Проверяются управляемые правила проекта. Файл CI учитывается при повторном
  запуске, если он записан в lock, независимо от `enforce`. Заготовки
  (`AGENTS.md`, README рабочих материалов, мастер-план) принадлежат проекту.
- Одна находка на путь. В тексте — версия программы и конкретное действие
  при `lipi init`, в JSON — обычное поле `file`. Проверить добавление
  шаблона, изменение его содержимого и исключение из поставки.
- Если локальный файл правили вручную и новая версия заменит его содержимое,
  остаются обе находки: V3 сообщает о локальном изменении, V4 предлагает
  посмотреть `lipi init --dry-run` и сохранить нужные правки перед заменой.
- Если шаблон исключили из поставки, V4 указывает прежний путь и сообщает:
  «Правило исключено из поставки. При `lipi init` запись будет удалена из
  lock, а существующий файл останется на диске». Проверить на временном
  проекте вывод `lipi init --dry-run` и результат обычного `lipi init`.

## Проверка кандидата 1.2.0

На проекте, развёрнутом с тега `v1.1.0`, V4 и `lipi init --dry-run` указали
одни и те же правила: `.agents/lipi/README.md` и `.agents/lipi/documentation.md`.
После `lipi init` проверка прошла без находок. Текст проверен на английском и
русском, JSON совпал. В отдельной установке `pipx --editable` изменение
шаблона без смены версии дало одну V4. После локальной правки того же файла
появилась также V3, а V4 предложила предварительный просмотр.

С настройкой `"codes": {"V4": "off"}` обе опубликованные версии 1.1.x
(1.1.0 и 1.1.1) выдали C1 и код возврата 2.
