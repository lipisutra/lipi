# Цели связей, статус цели и контракт среза

- Created: 2026-11-16
- Updated: 2026-11-17
- Status: accepted

## Контекст

Связи между описанием, кодом и рабочими документами помогают выбрать,
что прочитать и проверить перед задачей. Для среза нужны однозначные
цели, понятный порядок чтения и предел ответа. Статус рабочего документа
влияет на то, можно ли опираться на него при правке.

## Decision

### Цели связей и формат метки

- `@trace <путь>#<якорь>` — раздел любого Markdown-файла проекта вне
  пропускаемых каталогов (`skip_dirs`), включая `AGENTS.md` и `.agents/`:
  описание, правила исполнителя, страницы решений. Путь — от корня
  проекта. Якорь явный
  ([ADR-002](adr-002-tolko-yavnye-yakorya-metka-ukazyvaet-stranicu.md)).
- Обход исходников в поисках меток и разрешение целей имеют разные
  исключения: пропуск `.agents/` при обходе кода не запрещает её как цель.
  Из целей исключены `.agents/lipi/`, чьи файлы заменяет `lipi init`,
  и `<workflow>/history/` — архив вне проверок. Номера документов в
  архиве не ищутся.
- `@trace <ТИП>-<номер>` — рабочий документ по номеру: `ADR-018`,
  `ISS-001` или `PLN-120`. Документ ищется по типу и номеру.
- `covers` в справке записывается в той же форме.
- Разрешение целей общее для меток и covers; ошибка цели у `@trace` —
  T1, у covers — D6. Смысл существующих кодов сохраняется; T3 применяется
  к обеим формам.

### Статус цели — проверка T3

Метка или `covers` на рабочий документ, который сам говорит «больше не
действует», — T3, по умолчанию предупреждение, уровень меняется ключом
`codes` ([ADR-012](adr-012-urovni-proverok-nastraivayutsya-v-proekte.md)).

| Тип | Без сигнала | T3 |
| --- | --- | --- |
| Решение | предложено, принято | заменено, отклонено |
| Замечание | открыто, в работе | закрыто |
| План | новый, в работе, на приёмке, отложен | завершён, отменён |
| Обсуждение | открыто | закрыто |
| Аудит | всегда | — |

- Для заменённого решения сигнал называет первый рабочий документ, на
  который ссылается «Итог» в шапке, — то, что пришло на смену.
- Сообщение говорит, что делать: «закрыто — обход больше не нужен»,
  «заменено ADR-010 — сверьте код с новым решением».
- Раздел Markdown-файла статуса не имеет; T3 к нему не относится.
- Ошибкой по умолчанию T3 не делается: код работает, карта сообщает, что
  его основание ушло.

### Срез: что он делает и чего не делает

- `lipi slice <цель>` только читает: не пишет файлов (и `INDEX.md`), не
  меняет базовую линию, не запускает проверки проекта (P1). Ему нужны граф,
  статусы целей и `git blame`.
- Вне git-репозитория сводка говорит «устаревание не проверено (нет git)».
- Устаревание в срезе может проверяться частично: общий отбор по истории
  охватывает всё и засчитывает заведомо актуальные места как проверенные.
  Индивидуальный blame и поиск переносов ограничены фиксированным числом
  файлов в порядке точек входа, кода и тестов, внутри — по пути.
  Непроверенные подозрения не становятся сигналами. Рядом со
  сводкой всегда указан объём проверенных мест; `lipi audit` остаётся
  полной проверкой без предела. Точный предел и подсчёт — в описании среза.
- Уровни проекта из `codes` действуют и в срезе: выключенная проверка не
  даёт сигналов и не считается в сводке.

### Цель среза

- Форма различима сама: `путь#якорь` — раздел; путь к `.md` — страница;
  другой путь — файл кода; `ТИП-номер` — работа.
- Поиск без релевантности: точное совпадение; иначе подстрока среди якорей
  и номеров; иначе подстрока среди заголовков. Ничего не подошло или
  подошло несколько — подсказки (до 5 кандидатов) и ненулевой код возврата.
- Страница без якоря: срез не отказывает, а перечисляет её якоря-понятия с
  числом мест в коде у каждого и сигналы по странице.

### Что считается связанным

- **Обязательно соблюдать** — действующие решения (принято) и разделы
  правил исполнителя (`AGENTS.md`, `.agents/`, кроме `.agents/lipi/`).
  Связь с целью — любая из двух, и в ответе сказано, какая:
  - документ ссылается на цель;
  - в коде у того же объявления, что и метка на цель, стоит метка на этот
    документ.
- Заменённые и отклонённые решения в этот блок не попадают — они в сигналах.
- **Работа затрагивает** места кода с меткой на её номер и цели, на которые
  она ссылается. Цели показываются заголовками и числом мест в коде; их
  собственные срезы не раскрываются.
- **Тесты** — файлы слоя с именем `tests` и файлы, совпавшие с шаблонами
  `test_*`, `*_test.*`, `*.test.*`, `*.spec.*`, `*Test.*`. Ключ `tests` в
  `lipi.json` (список шаблонов) заменяет шаблоны по умолчанию.
- **Слои** — ключ `layers`: шаблон пути → имя слоя; порядок ключей —
  порядок вывода. Без настройки слой — каталог верхнего уровня; места,
  совпавшие с `entry`, идут первыми, дальше по алфавиту.
- **Глубина** — по явным связям, по умолчанию 1. `--depth 2..3` добавляет
  соседей соседей только заголовками. Общий код соседей не порождает; в
  срезе от кода он показан строкой «реализует ещё N понятий».

### Ответ

- **Порядок блоков.** Сигналы — всегда первыми и не скрываются фильтром
  остальных блоков: правка по устаревшему описанию опаснее неудобного
  порядка чтения. Ошибки и предупреждения получают место первыми, но
  не весь предел: остальным блокам гарантирована доля, точное
  распределение — в описании среза. Открытые работы по месту (`info`)
  делят предел наравне с остальными блоками. Остальное — по
  виду цели:

  | Цель | После сигналов |
  | --- | --- |
  | раздел, решение | соблюдать; выдержка; точки входа, затем слои; тесты; соседи |
  | страница | соблюдать; её понятия-якоря с числом мест в коде; точки входа, затем слои; тесты; соседи |
  | файл кода | соблюдать; понятия файла; тесты, которые прогнать; другие места тех же понятий; соседи |
  | работа | места с меткой на номер; цели работы; соседи |

- **Сводка первой строкой**: «2 предупреждения · 1 решение · 3 точки
  входа · 11 мест в коде (4 слоя) · 6 тестов · 2 открытые работы».
  Она считает весь результат до обрезки; устаревание — только по
  проверенной части с явным объёмом проверенного и непроверенного.
- **Выдержка** — только у самой цели. Раздел целиком, если влезает в
  предел; иначе первый абзац, заголовки подразделов и ссылки раздела, с
  пометкой об обрезке. Соседи — только заголовок и путь. Полный текст
  цели можно запросить отдельно от ограничения остальных блоков.
- **Предел общий для ответа**, а не отдельный для каждого блока или узла.
  Текст и JSON показывают одинаковое выбранное содержимое; представление
  не меняет отбор. При обрезке сказано, что скрыто и как получить остаток.
  Запрос полной выдержки освобождает от предела только саму выдержку,
  остальные блоки сохраняют общий бюджет даже для хаб-файла. Единицы
  подсчёта, параметры и формы элементов заданы в
  [договоре вывода](../../docs/ru/slice-output.md).
- **Пустые срезы** отвечают канонично: «меток нет — ищите по коду»;
  «работа ни на что не ссылается и меток на неё нет»; «кода по этому
  решению нет»; «в слоях X, Y меток нет».
- **JSON — договор с потребителем.** Поле `schema` с номером; `summary`
  теми же числами, что в строке сводки; `blocks` в порядке вывода, у
  каждого `kind`, `items`, `omitted` (число скрытых) и `hint`; общий
  `incomplete`; `checks.staleness` — объект со `state` (`full`, `partial`,
  `no-git`), числом проверенных мест `checked` и общим числом `total`.
  Удаление или смена смысла ключа — несовместимое изменение, новый номер
  схемы и мажорный выпуск; добавление ключа — нет.

### Покрытие

Отсутствие связи с кодом или тестами отображается в карте. По числу
меток нельзя судить о полноте реализации или тестирования.

## Альтернативы

- T3 ошибкой по умолчанию. Отвергнуто: код по заменённому решению
  работает; отчёт, а не барьер.
- Срез по работе как объединение полных срезов её целей. Отвергнуто:
  ломает предел и глубину; код ссылается на работу сам, меткой на номер.
- Поиск цели по релевантности. Отвергнуто: дорог, недетерминирован, а нужна
  одна строка подсказки.
- Предел на каждый блок. Отвергнуто: при нескольких больших блоках ответ всё
  равно разрастается.

## Последствия

  на рабочий документ по номеру; путь от корня проекта.
- Правила целей используют проверка, срез и карта. Подробности среза
