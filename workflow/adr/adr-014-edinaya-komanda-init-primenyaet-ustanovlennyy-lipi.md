# Единая команда init применяет установленный lipi

- Created: 2026-11-17
- Updated: 2026-11-17
- Status: accepted

## Контекст

Первое подключение проекта и применение обновлённых правил используют
одни шаблоны. Программа устанавливается отдельно от проекта
по [ADR-010](adr-010-cheker-tolko-v-ustanovlennoy-komande-lipi.md).

## Decision

Установленные правила применяет идемпотентная команда `lipi init [папка]`:

- Первое и повторное развёртывание различаются только наличием
  `.agents/lipi/lipi.lock`. Есть lock — повторное, нет — первое.
  Повреждённый lock — ошибка до записи, а не повод считать запуск первым.
- При первом развёртывании без `lipi.json` создаются настройки и недостающие
  заготовки. Существующие пользовательские файлы сохраняются. Если
  `lipi.json` уже есть, его настройки и заготовки проекта не меняются:
  создаются недостающие файлы lipi. Существующие файлы lipi при первом
  развёртывании сохраняются, их соответствие шаблонам проверяет V3.
  Существующий `AGENTS.md` сохраняется дословно: если ссылки на правила
  нет, команда предлагает добавить её вручную. Новая заготовка содержит ссылку.
- Повторное применение заменяет управляемые файлы lipi из установленного
  пакета и приводит его хук к `enforce`. Удалённые заготовки проекта заново
  не создаются, базовая линия повторно не формируется и не расширяется.
  При наличии lock удалённые файлы lipi восстанавливаются: это повторное
  применение, а не первое развёртывание. Без `lipi.json` повторный запуск
  завершается ошибкой с просьбой восстановить настройки.
- Настройки существующего проекта берутся из `lipi.json`; значения по
  умолчанию аргументов не перезаписывают их. Явные `--type`, `--docs`,
  `--workflow`, `--enforce`, расходящиеся с настройками, дают ошибку до
  записи с подсказкой изменить ключ в `lipi.json`. Совпадающие допустимы.
  У нового проекта `--enforce` включает строгость; без него она выключена.
  `--ci github` подключает управляемый шаблон, а не меняет ключ настройки.
  Чужой хук сохраняется.
- Изменённый проектом управляемый файл заменяется по ADR-009. Каждый такой
  файл, чей отпечаток расходится с lock, назван в отчёте:
  «ваши правки в X заменены»; в `--dry-run` — «будут заменены».
- `--dry-run` показывает изменения без записи. Повторное применение без
  изменений не меняет файлы; вывод называет установленную версию правил.
- Установкой программы управляет pipx. `lipi init` читает файлы
  установленного пакета и работает без сети.
- Если проект развёрнут более новой мажорной версией, нужен подходящий
  пакет. Раскладка рабочих документов описана в
  [ADR-020](adr-020-rabochie-dokumenty-po-godam-sozdaniya.md).

## Последствия

Команда применяет готовые правила из пакета. Проект хранит настройки,
заготовки и состояние. Проверки охватывают их сохранность, повторное
применение, чужой хук и `--dry-run`.
