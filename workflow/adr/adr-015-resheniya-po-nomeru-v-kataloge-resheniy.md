# Решения по номеру в каталоге решений

- Created: 2026-11-17
- Updated: 2026-11-17
- Status: accepted

## Контекст

Решения могут лежать рядом с описанием, в рабочих материалах или в
отдельном каталоге проекта. Ссылка по номеру должна переживать перемещение,
а для среза важно отличать обязательное уточнение от обычной ссылки.

## Decision

### Каталог решений

- Необязательный ключ `decisions` в `lipi.json` — каталог решений от корня
  проекта, например `"docs/adr"`. Без ключа решения ищутся в
  `<workflow>/adr/`. С ключом — только в нём; при `"workflow": null` ключ
  работает так же.
- Тип документа задаёт каталог решений, а не родительский каталог:
  решение в `docs/adr` — решение, а не страница описания. Для него
  действуют проверки шапки, ссылок и якорей; D3 и D4 — нет.

### Номер

- Номер — ведущие цифры имени файла в каталоге решений: `001-…`, `0001-…`
  и `adr-001-…` — это `ADR-001`, ведущие нули не важны.
- Нормализация одна для меток, `covers`, среза и поиска дублей.
- Два разных файла с одним номером — неоднозначность: T1 у `@trace`,
  D6 у `covers`, срез отвечает кандидатами. Один файл, найденный дважды,
  — не дубль.
- Новое решение `lipi new adr` создаёт в каталоге решений по его же
  соглашению об имени: если в каталоге уже есть файлы без префикса, —
  без префикса, с той же шириной номера.

### Статус и шапка

- Статус — только в формате lipi: `- Статус: <значение>` из списка
  решений (предложено, принято, заменено, отклонено). Чужие форматы шапок
  lipi не разбирает: проект один раз приводит их к формату lipi.
- Уточнение — не статус. Уточняющее решение несёт строку
  `- Уточняет: [ADR-NNN](…)`; уточнённое остаётся «принято». Строк
  «Уточняет» может быть несколько.

### Связи и проверки

- D5 разрешает ссылки из описания на решения, где бы они ни лежали; на
  планы, замечания, обсуждения и аудиты остаются отдельными типами рабочих документов.
- T3 распространяется на обычные ссылки из описания и правил исполнителя
  на решение «заменено» или «отклонено». Сообщение фактическое: «ссылка
  ведёт на заменённое решение ADR-NNN — проверьте актуальность текста».
  Обычная ссылка может упоминать прежнее решение для сравнения; сигнал не
  утверждает, что текст ему следует.
- Срез, блок «соблюдать», для уточнений:
  - цель — уточнённое решение: в блоке и оно, и его принятые
    уточняющие решения;
  - цель — уточняющее решение: в блоке и оно, и то, что оно уточняет;
  - цель — раздел или файл кода с меткой на решение: решение и его
    принятые уточнения.

  Остальные ссылки между решениями дают только «контекст»: связь
  «соблюдать оба» возникает лишь из строки «Уточняет».
  В «соблюдать» входят только принятые решения; заменённое или отклонённое
  основание даёт T3, а не становится обязательством.
  Цепи обходятся направленно: по ADR — основания вверх и уточнения вниз,
  по разделу или коду — уточнения вниз. От найденного предка к другим его
  уточнениям обход не переходит. Непринятое решение завершает ветвь и даёт
  сигнал статуса; циклы не повторяют узлы. Ограничение вывода применяется
  после сбора связей.

## Альтернативы

- Номер только из `adr-NNN-…`. Отвергнуто: не находит самые
  распространённые раскладки.
- Номер или статус в чужих форматах шапок (`**Статус:**`, `Status:`,
  «amended by»). Отвергнуто: подгонка под каждый формат.
- Статус «уточнено». Отвергнуто: уточнённое решение действует; это связь,
  а не состояние.
- Любая ссылка между решениями как обязательство. Отвергнуто: ссылка
  может быть сравнением.

## Последствия

Поиск решений, нормализация номеров и строки «Уточняет» общие для
проверок и среза. Каталог решений можно подключить отдельно при
`"workflow": null`. Решения и их приложения обрабатываются отдельно
от описания и кода. Ссылки приложений входят в граф и цепочку
устаревания. Договор описан в [настройках](../../docs/ru/settings.md)
и [срезе](../../docs/ru/slice.md).
