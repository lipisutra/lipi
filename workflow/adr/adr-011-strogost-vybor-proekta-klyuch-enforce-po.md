# Строгость — выбор проекта: ключ enforce, по умолчанию lipi не блокирует

- Created: 2026-11-16
- Updated: 2026-11-16
- Status: accepted

## Контекст

Отчёт о находках полезен уже при подключении проекта. Блокирующий
pre-commit требует установить lipi на машинах, где делают коммиты,
поэтому его включение решает сам проект.

## Decision

- `enforce` в `lipi.json` — логический ключ, по умолчанию `false`.
- При `false` локальная проверка выдаёт отчёт. Правила исполнителя просят
  исправлять ошибки своей правки или сообщать о них пользователю.
  `lipi init` убирает управляемый lipi pre-commit, если он есть.
- При `true` команда `lipi init` ставит pre-commit
  `lipi check --staged`. Правила исполнителя требуют исправить ошибки
  до коммита.
- Хук опознаётся по маркеру `# lipi`. Чужой хук сохраняется. После смены
  `enforce` нужно применить правила через `lipi init`. До этого V3
  сообщает о расхождении, а `lipi doctor` проверяет наличие хука.
- Код возврата `lipi check` определяется находками и корректностью
  запуска. В управляемом CI `enforce` задаёт, блокируют ли ошибки прогон.

## Последствия

Проект может начать с отчёта и включить строгий режим, когда готов
проверять каждый коммит. Дисциплина выпусков
([ADR-010](adr-010-cheker-tolko-v-ustanovlennoy-komande-lipi.md)) защищает
проекты с блокирующей проверкой от внезапного появления новых ошибок.
