# Рабочие документы по годам создания

- Created: 2026-11-18
- Updated: 2026-11-18
- Status: accepted

## Контекст

Каталог типа документов в активном проекте может вырасти до сотен
файлов. Разделение по годам создания ограничивает размер каждого каталога.
Путь должен быть стабильным при смене статуса.

## Decision

### Раскладка

- Планы, замечания, обсуждения и аудиты лежат в подкаталоге года
  создания: `<workflow>/plan/2026/pln-120-….md`,
  `<workflow>/audit/2026/aud-003-тема/aud-003-readme.md`.
- Год — из «Даты создания» в шапке. Место выбирается один раз при
  `lipi new` и больше не меняется: смена статуса документ не двигает.
- Решения — плоско, без годов: в `<workflow>/adr/` и в каталоге из ключа
  `decisions`. Их мало, на них ссылается описание, а у внешнего каталога
  решений своё соглашение.
- Замечания к lipi в `.agents/lipi-feedback/` — плоско: их забирает
  `lipi collect`.
- Номер сквозной по типу через все годы и архив. По номеру `PLN-120`
  можно однозначно найти план независимо от года.

### Дата закрытия

- При переходе в финальный статус исполнитель записывает в шапке рядом
  с «Итогом» строку `- Дата закрытия: ГГГГ-ММ-ДД`. Она обязательна для
  завершённого/отменённого плана, закрытого замечания/обсуждения,
  заменённого/отклонённого решения. У аудита нет статуса и даты закрытия.
- Это дата данного закрытия: последующие правки текста, переименования
  и смена одного финального статуса на другой её не обновляют. Если работу
  открыли вновь, она возвращается в живую часть указателя; при новом
  закрытии исполнитель явно записывает новую дату.
- Год страницы журнала берётся только из этой строки. Генератор указателя
  не читает историю Git для дат, не использует дату обновления вместо неё
  и не меняет шапки. Правило одинаково с Git и без него.
- Правка заголовка, Итога или адреса обновляет строку на странице того же
  года; совпадающее содержимое указателя не переписывается. Год создания
  по-прежнему определяет путь документа, а не его место в журнале.

### Проверки

- Документ плана, замечания, обсуждения или аудита прямо в каталоге типа,
  без года, — ошибка: раскладка нарушена.
- Год каталога не совпадает с годом «Даты создания» — предупреждение с
  подсказкой `lipi mv`.
- Решение в подкаталоге года — ошибка.
- Финальный статус без «Даты закрытия» — W4, как отсутствие обязательного
  Итога. Некорректная календарная дата, дата раньше Даты создания или
  позже сегодняшнего дня — W3, как другие ошибки шапки.
  Список документов, которым требуется Итог, задан в [правилах](../../docs/ru/rules.md#workflow).

### Раскладка оформленных материалов при подключении

- Для оформленных документов, лежащих прямо в каталогах типа, `lipi init`
  применяет механизм массового переноса
  ([ADR-017](adr-017-perenos-stranicy-komandoy-lipi-mv-i.md)). Ссылки, метки и
  `covers` на перенесённые документы и относительные ссылки внутри них
  переписываются за один проход, всё или ничего.
- `--dry-run` показывает полный план. Грязные затрагиваемые файлы — отказ
  до записи со списком, как у массового переноса.
- Закрытым документам без «Даты закрытия» перевод однократно добавляет
  строку: по коммиту закрытия из Git, а без истории — по «Дате обновления».
  Каждое значение и его источник видны в dry-run. Ошибка чтения или
  неоднозначность истории, неверная исходная дата — отказ, а не выдуманная
  дата. Уже указанная корректная дата сохраняется; повторный init её
  не пересчитывает. Историю для этого читает только переводчик.
  Fallback даты не отменяет отказ переноса плоских материалов без Git.
- Строка добавляется и закрытым ADR/feedback, хотя их пути не меняются.
  Архив не затрагивается. Однократное дополнение шапки закрытого обсуждения
  разрешено как перевод формата; его текст и Итог не переписываются.
  Даты создания и обновления не подменяются датой переноса.
- Базовая линия переводится вместе с файлами: её записи по путям
  перенесённых документов получают новые пути, иначе прежние ошибки
  вернутся как новые.
- Отметки просмотра переводятся тем же планом по
  [договору ADR-019](adr-019-otmetki-prosmotra-ustarevaniya-po-sostoyaniyu-svyazannyh/review-contract.md):
  пути, отпечатки доказанных адресных замен и id, с сохранением автора,
  даты и объяснения. Это не новый просмотр. Остальные правки init не
  получают такого подтверждения; устаревшие записи не освежаются.
- Архив `history/` не переводится: он вне проверок; номера в нём
  по-прежнему заняты.
- `lipi migrate` (перенос рабочих материалов не в формате lipi) сразу
  раскладывает по годам: год из даты в шапке, иначе из даты первого
  коммита файла, иначе год переноса — и так сказано в плане.

## Альтернативы

- Год и месяц. Отвергнуто: даже у самого активного проекта год даёт
  50–120 документов на тип; месяцы дают пустые папки и глубину.
- Раскладка по статусу или перенос старого в архив. Отвергнуто: ломает
  ссылки при каждой смене статуса.
- Гранулярность в настройках. Отвергнуто: разные раскладки придётся
  сводить; смена гранулярности — снова переезд.
- Вычислять год закрытия по Git при каждой пересборке указателя.
  Отвергнуто: повторная реконструкция переходов, переименований и слияний
  хрупка, а без Git не даёт устойчивого года. Дата записывается в шапке;
  прежняя история используется только при первоначальном переводе.

## Последствия

Год создания определяет путь, год закрытия определяет страницу журнала,
а номер связывает документ с кодом и другими материалами. Возможности
указателей, требование к Git и отказ при грязных файлах описаны в
[справочнике](../../docs/ru/workflow.md#upgrade).
