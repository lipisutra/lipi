# Связи между репозиториями через явные подключения

- Created: 2026-11-18
- Updated: 2026-11-18
- Status: accepted

## Контекст

Описание общего API и его потребители могут находиться в отдельных
репозиториях. Для проверки связей нужно явно знать, какие каталоги
можно читать и какие цели разрешено использовать.

## Decision

### Подключения

- Ключ `repos` в `lipi.json`: имя подключения → `path` (путь от корня
  проекта) и `read` — что из соседа читается: `docs`, `decisions`, `code`,
  `tests`. `docs`/`decisions` — для внешних целей, `code`/`tests` — для
  поиска потребителей. Подключение — не зависимость программы.
- Имя — строчные латинские буквы, цифры и дефис. Неверный ключ — C1.
  В режиме подключений имя слоя не содержит `::`, иначе C1.
- Читаются только перечисленные подключения и только объявленные
  возможности. Настройки подключений соседа читаются лишь для того, чтобы
  распознать его ссылки на этот проект; к третьим репозиториям перехода
  нет. Сопоставление — по разрешённому корню, а не по имени подключения.
  Каталоги и исключения соседа — из его `lipi.json`; без него — только
  цели `путь#якорь`.
- Два подключения к одному физическому корню и подключение к самому
  проекту — C1.
- `read` проверяет тип документа-цели, а не форму ссылки:

  | Цель | Нужно в `read` | Иначе |
  | --- | --- | --- |
  | раздел описания соседа | `docs` | T1 у метки, D6 у `covers`: цель вне разрешённого чтения |
  | решение соседа — по номеру или по пути с якорем | `decisions` | то же |
  | поиск потребителей у соседа | `code`, `tests` | сосед в обратный поиск не входит |
  | план, замечание, обсуждение, аудит соседа — в любой форме | не поддерживается | T1 / D6: внешние работы не поддерживаются |
  Сосед на другой первой цифре lipi считается недоступным с причиной.
- Путь проходит проверку после разрешения символических ссылок: граница
  не обходится. Сети, клонирования и запуска чужих `checks` нет; сосед не
  меняется.

### Формат метки

- Внешняя цель: `@trace <имя>::<цель>`, например `core::docs/protocol.md#request`
  и `core::ADR-018`; `covers` — в той же форме. Без префикса цель всегда
  локальная; ненайденный номер по соседям не ищется.
- Метка без имени подключения разрешается в текущем проекте.
- Репозиторий различается везде: в JSON, сообщениях, subject базовой линии
  (`core::ADR-018 заменено`).

### Недоступность

| Случай | Поведение |
| --- | --- |
| имя подключения неизвестно | T1 у метки, D6 у `covers` |
| сосед прочитан, цели в нём нет | T1 / D6 |
| подключение известно, прочитать не удалось | T4 — предупреждение «<имя> недоступен: <причина> — связь не проверена», уровень через `codes`; T3 не вычисляется |

`lipi check` с T4 не выглядит чистым: связи не проверены — это находка.
`"T4": "off"` скрывает только находку: подключение остаётся непрочитанным
в ответе среза и карты, неполнота и охват сохраняются.

### Версия

- Читается рабочее дерево по пути. Каждый ответ среза и карты называет
  прочитанные подключения: HEAD и признак незакоммиченных изменений. В
  JSON — `checks.repos` и общий `reproducible`: он учитывает и свой
  репозиторий; грязное дерево, недоступность или отсутствие git дают
  `false`; неизвестные `head` и `dirty` — `null`, а не «чисто».
- Поля подключений (`repo`, `checks.repos`, `reproducible`) появляются
  только в режиме с `repos`.
- Режим закреплённого коммита — отдельное решение позже; отсутствующий
  коммит не подменяется деревом.

### Срез и карта

- Срез по внешней цели — по договору среза: выдержка и связи из соседа,
  места своего кода.
- Обратное направление: срез по своему понятию показывает места в
  соседях с `read: code` или `tests`, чьи метки ведут на это понятие —
  подключение соседа разрешается в корень этого проекта. Места идут
  отдельной группой слоёв `<имя>::<слой>`. Охват — «найдено среди
  перечисленных и доступных»; он назван в сводке.
- «Соблюдать»: правила исполнителя соседа не импортируются; входят только
  решения соседа, на которые местный код указал явно, вместе с принятыми
  уточнениями из того же источника по ADR-015. Требуется `read: decisions`;
  это не переход к третьим репозиториям.
- T2, A4 и устаревание между репозиториями не вычисляются. Внешние связи —
  «проверьте» с пометкой «межрепозиторное устаревание не проверено».
- `lipi map`: столбцы подключений с `read: code`/`tests`.

## Альтернативы

- Поиск ненайденной цели по всем соседям. Отвергнуто: новое подключение
  молча меняет смысл старых меток.
- Отдельный список «участников обзора». Отвергнуто: хватает `read` у
  одного списка подключений.
- Недоступный сосед — молчание. Отвергнуто: проверка выглядела бы чистой,
  не проверив связи.
- Межрепозиторное устаревание по blame. Отвергнуто: при раздельных
  выпусках «код новее документа» не говорит о согласованности.
- Монорепозиторий или подмодули git остаются альтернативой проекта: с
  ними lipi работает без подключений.

## Последствия

- Модель целей и индекс среза используют текущий проект и его прямые
  подключения. Условия чтения описаны в [настройках](../../docs/ru/settings.md#repos).
