# Срез по изменению договора

- Created: 2026-11-21
- Updated: 2026-11-21
- Status: in progress

## Purpose

Дать ревьюеру один срез от правки требования до мест в коде и тестах, которые стоит открыть. Основание и критерии — в [ISS-023](../../issue/2026/iss-023-srez-po-diffu-ot-izmeneniya-dogovora.md). Достаточно существующих меток.

Целевой выпуск — **1.3.0**. Версию и CHANGELOG обновить с первой правкой поведения.

## Подход

На Lipi 1.2.1 проверен пример из ISS. Правка порядка полей под `#row` дала пустой срез. После замены якоря на `#record` и исправления метки функции срез показал одно понятие. Тест с прежней меткой отсутствовал и в `--diff HEAD`, и в `--staged`.

В `slice_diff.py` уже есть пути, снимки файлов и диапазоны изменённых строк с обеих сторон. Сейчас Markdown отбрасывается, а метки обеих сторон разрешаются по текущему индексу. Использовать тот же дифф для отбора разделов и сохранить прежние адреса там, где их уже нельзя разрешить. Дифф остаётся локальным; подключённые источники дают места в доступной версии.

## Шаги

### З1. Разделы на двух сторонах диффа

- По [правилам выбора изменений](../../../docs/ru/slice-diff.md#selection) в `--diff REV` сравнить ревизию с рабочим деревом, в `--staged` — HEAD с индексом, до первого коммита — пустое дерево с индексом. Для каждого изменённого Markdown-файла применить правила допустимой цели, включая решения и рабочие документы. Удалённый файл читать из Git. Проверить исключения проекта, в том числе архив.
- Сопоставить диапазоны изменённых строк с `anchor_region` каждой стороны. Сохранить адрес и формулировку раздела до и после правки. Для добавленной или удалённой цели явно различить отсутствующую сторону. При замене имени показать удаление и добавление по точным адресам.
- Посчитать непрерывные участки вне всех областей отдельно от существующего счётчика правок кода. Как у кода, для каждого фрагмента взять большее число участков с двух сторон. Проверить правку вступления, подзаголовок внутри размеченного раздела, заголовок таблицы, общий для нескольких размеченных строк, и неподготовленную правку поверх индекса.

### З2. Места по текущим и прежним адресам

- В `slice_index.py` и `repo_index.py` использовать существующий разбор групп меток. Для удалённых целей сохранить возможность найти исходный адрес в том числе у неизменённой метки, отброшенной при обычном разрешении. Для изменённых файлов читать также прежние группы и их позиции. Различать связь, снятую в диффе, и всё ещё существующую ссылку на удалённую цель.
- В одном срезе объединить основания из правок кода и договора. Показывать изменённое место, если оно само связано с изменённым договором. Метки на изменённый ADR по номеру показывать с отдельным основанием. Одно место с номером и якорем выводить один раз с обоими основаниями.
- Взять локальные и внешние места через одни правила сборки. У соседа искать только в разрешённых областях `code` и `tests`, с учётом того, на чей договор указывает метка. На двух репозиториях проверить видимый код при скрытых тестах, затем недоступный источник. В сводке указать, что удалось прочитать; сигналов устаревания для внешних связей это не добавляет.

- В [JSON схемы 1](../../../docs/ru/slice-diff.md#json) добавить машинно различимые основания и прежнюю и новую выдержки. Сохранить типы и смысл существующих полей, в том числе `via`, `matched_targets`, `checks.diff.files` и `checks.diff.unmarked`. Примером ответа закрепить вид добавленной и удалённой цели.
- **Проверка З2.** В примере из ISS заменить `#row` на `#record` и исправить только метку функции. В ответе `lipi slice --diff HEAD --format json` проверить обе цели: `#row` удалена, `#record` добавлена. Функция указана один раз с исправленной связью, тест по-прежнему ссылается на удалённую цель. Подготовить тот же дифф и проверить те же утверждения через `lipi slice --staged --format json`.

### З3. Текстовый вывод, описание и приёмка

- Применить [общий предел](../../../docs/ru/slice-output.md#budget) к обеим выдержкам вместе. В тексте и JSON проверить одинаковый отбор, пометку обрезки и полные формулировки при `--full`. Показать отдельно число участков вне якорей и изменённый раздел без найденных связей в просмотренных источниках.
- Обновить сообщения и справку о срезе на английском и русском, добавить пример смешанного диффа в обе редакции.

## Completion criteria

1. На одном небольшом проекте изменить только порядок полей в договоре. Видны обе формулировки, функция записи и тест чтения; результат воспроизводится через `--diff HEAD` и после подготовки файлов через `--staged`.
2. На том же проекте заменить `#row` на `#record`, исправить метку функции, оставить прежнюю у теста. Из одного вывода понятно, что исправлено и куда идти дальше. `lipi check` даёт T1 только для забытой метки. Отдельно удалить якорь без замены, затем снять метку в том же диффе и проверить, что прежняя связь различима.
3. **Совместимость с 1.2.1.** Для диффа без изменений в Markdown срез совпадает с результатом `v1.2.1`: текст побайтно, JSON по всем полям и значениям, включая порядок элементов списков. Закрепить это регрессионным тестом для `--diff HEAD` и `--staged` на одной правке кода с существующими метками. Эталон снять с тега при тех же настройках, языке и состоянии Git.
4. По шагам прогнать адресные тесты Git, среза и подключений. В конце — полный локальный набор на обоих языках, `lipi check` и `lipi audit`. Сверить текст и JSON главного примера, включая пометку удаления, и записать результаты в план.
