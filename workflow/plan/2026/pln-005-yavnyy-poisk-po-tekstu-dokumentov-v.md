# Явный поиск по тексту документов в срезе

- Created: 2026-11-22
- Updated: 2026-11-22
- Status: in progress

## Purpose

После промаха по вопросу человек или агент может найти подходящий абзац,
открыть его в редакторе или перейти к обычному срезу. Основание и примеры
приёмки — в [ISS-027](../../issue/2026/iss-027-yavnyy-poisk-po-tekstu-dokumentov-cherez.md).

## Подход

На Lipi 1.3.3 обычный запрос «Сколько дней хранится копия?» в этом репозитории
возвращает код 1 и JSON `not-found` с пустым списком кандидатов. Существующие
точки входа — [поиск цели](../../../docs/ru/slice.md#target) и
[поиск у соседа](../../../docs/ru/slice-output.md#repo-search).
Полнотекстовый поиск запускать только по `--search`. При обычном промахе
достаточно сформировать команду с исходным вопросом.

Целевая версия — **1.4.0**. Открыть запись CHANGELOG
и поднять версию с первой правкой поведения. Выпуск согласуется отдельно.

## Шаги

### З1. Документы, совпадения и порядок

- Выделить из `slice_index.py` и `repo_index.py` перечисление доступных
  Markdown-страниц и их целей. При поиске читать страницы только выбранного
  источника. Применить существующие исключения, области `docs`, `decisions`
  и `page_dirs` соседа. Полный индекс сейчас обходит также код и связи.
  Для поиска достаточно страниц и их якорей.
- Искать в заголовках и видимом тексте абзаца, сохраняя физические номера
  строк Markdown. Для совпадения брать самый узкий содержащий его явный
  якорь по `anchor_region`, вне якоря — адрес страницы. Для каждого адреса
  оставить лучшую выдержку и строку совпадения, начиная с 1.
- Сопоставлять слова Unicode без учёта регистра. Для первого варианта проверить
  близкие формы с общим началом из четырёх и более букв и добавлением,
  удалением или заменой одной последней буквы. Короткие слова сравниваются
  целиком. Ориентиром остаются пары из ISS. Для `copies` и `copy` этот
  способ имеет известное ограничение.
- Считать, в скольких разных файлах выбранной области встречается каждое
  слово запроса с допустимой формой. Оценивать абзац по разным совпавшим
  словам. У редкого слова больший вес, у общего для всех страниц вес остаётся
  положительным. Точное совпадение при прочих равных выше совпадения
  по началу. При равенстве использовать адрес и строку для устойчивого порядка.
- Контроль шага — на малой фикстуре RU/EN проверить `НДС` и `API`,
  словоформы, ложные пары и порядок для «что если API недоступен».
  Повтор слова сто раз в одном файле учитывается один раз. В области из одной
  страницы точный запрос её находит. Добавление местных страниц не меняет
  порядок результатов у соседа.

### З2. Команда, результат и подсказки

- В `slice.py` добавить `lipi slice --search 'фраза'` и форму `'имя::фраза'`.
  Допустить `--format text|json`. Пустой запрос и несовместимые ключи среза
  (включая `--diff`, `--staged` и `--role`) дают ошибку вызова с кодом 2.
- Выводить до пяти кандидатов, по образцу обычного поиска цели.
  Показать, сколько найдено и сколько выведено. Даже единственный результат
  остаётся в списке. Текст и JSON схемы 1 строятся из одного списка.
  У кандидата — `repo`, `target`, `title`, `excerpt`, `file` и `line`.
  Пара `repo` + `target` задаёт адрес для `slice`. Путь `file` открывается из
  каталога запуска. При разных дисках Windows использовать абсолютный путь,
  как при открытии страницы соседа сегодня.
- Обычный текстовый `not-found` получает готовую команду в тексте и поле
  `search_command` в JSON. Сохранить существующие `suggestions` для поиска
  по заголовкам. Сверить с 1.3.3 обычный успех, неоднозначность и ошибку
  точного адреса. В локальном `--search` предложить команды `--search 'имя::фраза'`
  для доступных подключений с читаемыми страницами, в том числе при локальных
  совпадениях. Переиспользовать экранирование аргументов из `repo_slice.py`.
  Для подсказок достаточно настроек и доступности соседа.
- На прочитанной области код 0 означает хотя бы одного кандидата, код 1 —
  ноль. Для недоступного соседа сохранить отдельный исход среза с
  `incomplete: true` и кодом 0 с пояснением, что источник не удалось прочитать.
  Проверить также неизвестное имя, отсутствие `lipi.json` у соседа и страницу
  вне области чтения по действующим правилам подключений.
- Контроль шага — из CLI получить в JSON адрес `docs/storage.md#cleanup`,
  выдержку и строку 12. Открыть адрес обычным `slice` и сверить строку в файле.
  Повторить с локальным посторонним совпадением и нужной страницей в
  `page_dirs` соседа, из корня и подкаталога `src/`. Адрес среза и строка
  остаются теми же, путь от каталога запуска меняется.

### З3. Справка и сквозная приёмка

- Добавить сообщения и справку EN/RU, обновить отпечатки перевода и обе
  редакции описания среза. Показать короткую последовательность команд
  от обычного промаха до открытия одного результата. Пояснить коды выхода,
  ограничение словоформ и выбор читателя по выдержке.
- На временных репозиториях проверить поиск ответа в своём репозитории,
  у соседа и на вопрос без документированного ответа. В третьем
  сценарии различить пустую выдачу и кандидата с посторонней выдержкой.

## Completion criteria

Текст и JSON совпадают по составу, порядку, выдержкам и адресам кандидатов.
Переключение языка интерфейса сохраняет результат JSON и коды выхода.
Тестами CLI подтвердить, что обычный запрос без `--search` не запускает
поиск по абзацам, а подсказка не запускает его у соседа. На каждом шаге
прогнать адресные тесты. На приёмке — полный набор на английском и русском,
`lipi check` и `lipi audit`.
