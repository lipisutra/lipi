[English](../README.md)

Для того, кто меняет сам lipi. Тому, кто только разворачивает его в проекте,
достаточно [README](../../README.md).

lipi ведётся по собственным правилам, без исключений: проверяется как любой
проект — `lipi check` из редактируемой установки (`pipx install --editable .`).

Установка для разработки — из папки клона: `pipx install --editable .`; как
ставить и обновлять lipi, — в [README](../../README.md#install).

## Границы работы <a id="boundaries"></a>

Работа над lipi не выходит за пределы этого репозитория.

- План, замечание, обсуждение и решение lipi описывают только изменения в
  самом lipi: правила, шаблоны, чекер, скрипты, тесты и его собственное
  описание.
- Если задаче нужны изменения в другом проекте, они планируются и ведутся в
  том проекте, по его правилам. В рабочих материалах lipi их нет: ни срезов,
  ни шагов, ни критериев завершения.
- Статус работы lipi не зависит от коммитов в других репозиториях: работа
  завершена, когда завершено то, что сделано здесь.
- В документах, тестах и сообщениях коммитов нет названий и узнаваемых
  деталей конкретных чужих проектов. Замечания из внешних проектов
  обезличиваются; тестовые фикстуры синтетические и обобщённые.

## Как менять <a id="change"></a>

Правило, шаблон и чекер описывают одно и то же с трёх сторон, поэтому
меняются одним коммитом:

1. Основание — замечание в [указателе](../../workflow/INDEX.md) или прямая
   просьба. Трение из проектов сначала забирается: `python3 src/lipi/collect.py <проект>`.
2. Правка `docs/{en,ru}/rules.md` (что и почему), шаблона в `src/lipi/locale/<язык>/templates/` (как это
   написано для исполнителя) и соответствующего модуля `src/lipi/checker/`
   (как это проверяется).
3. Новая проверка получает случай в `tests/`: без него она не
   считается работающей.
4. При изменении поведения обновляются версия в `src/lipi/__init__.py`
   и запись в `CHANGELOG.md` по [порядку выпуска](#release).
5. Проверки ниже проходят.
6. Сообщение коммита упоминает ID работы, которую он двигает. Аудит A5
   определяет по нему отставание статуса.

Чего не делать:

- не добавлять правило, которое чекер не проверяет и которое нельзя записать
  исполнителю одной фразой;
- не вносить в правила особенности одного проекта: то, что зависит от языка
  и стека, остаётся в проекте;
- не добавлять внешние зависимости: чекер использует стандартную библиотеку.

Переводчику: источники — `src/lipi/locale/en/`. При добавлении языка
создайте соседнюю папку. В `messages.json` и `terms.json` запись перевода
содержит `text` и `source_sha256`. У термина `text` содержит название
(`term`) и короткое определение (`definition`). В `template-hashes.json`
ключ — путь заготовки `seed/…` относительно `templates/`. Управляемые правила и шаблон CI берутся только из английской папки. Отпечаток вычисляет
`lipi.i18n.fingerprint` по английскому значению или тексту шаблона в UTF-8.
После сверки перевода обновите отпечаток. Инвентаризация всех трёх частей —
`python3 -m unittest tests.test_interface_language.LanguageResources.test_translation_inventory`.

## Проверки <a id="checks"></a>

```bash
python3 -m unittest discover -s tests  # каркас чистый, каждое нарушение ловится
lipi check                             # сам lipi по своим правилам
lipi audit                             # аудит: залежавшиеся работы, статусы, базовая линия
lipi index
```

Состав поставленного описания и `lipi guide` проверяет
[`tests/check_package.py`](../../tests/check_package.py). После чистой установки pipx
запустите этот файл Python из установленного окружения, с `--source` на снимок
той же ревизии. Запуск — вне репозитория и снимка, без `PYTHONPATH`;
`--source` задаёт ожидаемые страницы и байты, а импорт идёт из установки.

Коммит и публикация — по явному поручению пользователя.

## Порядок выпуска <a id="release"></a>

Версия поднимается на первой задаче этапа, меняющей поведение: тогда же
появляется запись в `CHANGELOG.md`
([ADR-001](../../workflow/adr/adr-001-net-naslediya-sovmestimost-s-prezhnimi-versiyami.md)).
Выпуск — тег `vX.Y.Z` на коммите с этой записью:

1. У каждого выпуска после первого запись в `CHANGELOG.md` содержит
   раздел «Upgrading your project». Он начинается с двух пунктов, каждый
   на одной строке:

   ```text
   1. Upgrade Lipi with `pipx upgrade lipi`.
   2. The rules and templates are unchanged. You can skip `lipi init`.
   ```

   Если правила или шаблоны изменились, второй пункт формулируется как
   «2. The rules and templates have changed. Run `lipi init`.» Для установки
   точной версии можно указать команду
   `pipx install --force git+https://github.com/lipisutra/lipi@vX.Y.Z` с тегом
   этой записи. Остальные действия проекта идут после этих двух пунктов.
   Формат проверяет `tests/test_release.py`.
2. `tests/test_release.py` проходит: версия в `src/lipi/__init__.py`, верхний
   заголовок `CHANGELOG.md` и `.agents/lipi/lipi.lock` сходятся.
3. Аннотированный тег на коммите с записью `CHANGELOG.md` и пуш:

   ```bash
   git tag -a vX.Y.Z -m "lipi X.Y.Z"
   git push origin vX.Y.Z
   ```

4. CI на теге зелёный.

Тег первой цифры (`v1` для линии 1.x) передвигается на каждый выпуск: по нему
проекты ставят lipi в CI (ADR-010). Дисциплина выпусков: внутри одной первой
цифры новая проверка выходит только предупреждением, а повышение уровня с
предупреждения до ошибки — только при смене первой цифры. Это проверяет
`tests/test_release.py` против таблицы `CODE_LEVELS` на теге `v<цифра>.0.0`;
до первого тега новой линии пропускается только сравнение уровней,
а версия кода, CHANGELOG и lock проверяются. Ошибка чтения существующего
тега завершает проверку с ошибкой. При смене первой цифры новые уровни
ошибок перечисляются в `CHANGELOG.md`.

Несовместимое изменение формата в файлах проекта — метки `@trace`, `covers`,
шапки и имена рабочих документов, якоря — выходит только вместе с
автоматическим переводом: `lipi init` новой версии переписывает прежнюю
форму сам или печатает точный план замен, а тест проверяет перевод на
проекте в прежнем формате. Инструкция в `CHANGELOG.md` не заменяет перевод:
у проекта могут быть тысячи меток. Без перевода изменение формата не
выпускается.

Истории шаблонов в пакете нет (ADR-009): `lipi init` заменяет файлы lipi
целиком, поэтому снимки выпусков не нужны.
