# Срез по диффу

После правки `lipi slice` показывает связанные места, которые стоит
проверить. Связь сама по себе не означает, что код или описание неверны.
Общие блоки, предел, сигналы и схема ответа — в [договоре среза](slice.md).

## Выбор изменений <a id="selection"></a>

```bash
lipi slice --diff HEAD
lipi slice --diff HEAD --role consumes
lipi slice --diff v1.0.0 --format json
lipi slice --staged
```

Выберите один источник из трёх: цель, `--diff <база>` или `--staged`.
`--diff` сравнивает отслеживаемые файлы рабочего дерева с одной ревизией
Git, включая подготовленные и неподготовленные изменения. Неотслеживаемые
файлы не входят: сначала добавьте их в индекс. `--staged` сравнивает индекс
с HEAD, а до первого коммита — с пустым деревом. В этом режиме срез
берёт изменённые договоры и их формулировки из HEAD и индекса.

Изменения читаются без записи файлов, обновления индекса или запуска проверок
проекта. При поиске меток кода действуют обычные исключения для Markdown,
двоичных и слишком больших файлов, каталогов описания,
рабочих материалов и решений. Чистое переименование без правки строк не добавляет целей.

В Markdown, допустимом как цель метки, добавленные строки относятся к области
явного якоря в новой версии страницы, удалённые — в прежней. Границы области
те же, что у [A4](codes.md#a4). Правка подзаголовка входит в размеченный
родительский раздел, а правка шапки таблицы затрагивает каждую размеченную строку этой таблицы.

На обеих сторонах диффа строка кода относится к блоку меток до следующего
блока или конца файла. Добавленные строки используют новые метки,
удалённые — прежние, в том числе при удалении самой метки или файла.
При правке только кода номера и пути разрешаются по текущим документам проекта.
При правке договора срез также находит локальные метки, которые на прежней
стороне ссылались на старый адрес. У соседей доступны места из их рабочих деревьев.

## Ответ <a id="response"></a>

Блоки идут в порядке `signals`, `obey`, `concepts`, `entry`, `code`, `tests`,
`context`. В понятия входят изменённые разделы и разрешённые цели затронутых
меток с заголовками и числом мест в коде. По ним собираются принятые решения,
правила, уточнения и соседи, как в обычном срезе. В блоки кода и тестов
входят другие места с метками на эти цели, а также изменённое объявление,
если оно связано с изменённым договором. Общие понятия, основания и места
появляются по одному разу. Внешние цели и потребители входят по
[договору подключений](slice.md#repos).

В диффе только по коду с несколькими целями совпавшие адреса в `entry`,
`code` и `tests` перечисляются после «через». У мест, связанных с изменённым
договором, показаны цели и основания, в том числе метки на новый адрес и
сохранившиеся метки на удалённый якорь. В диффе с несколькими целями
адрес сокращается до `#якорь`, если якорь соответствует одной цели до
фильтрации и обрезки. У целей с одинаковым якорем и у целей без якоря
показываются полные адреса.

[Фильтр по роли](slice-output.md#roles) помогает найти читателей или
производителей изменённого договора. Если функция читает `#row` и формирует
`#summary`, правка одного `#row` покажет её как потребителя. При правке
обоих разделов видны обе связи по одному адресу. Для сохранившейся или
добавленной связи берётся новая роль, для снятой — прежняя. Живая метка
на удалённый якорь сохраняет свою роль. В `--staged` новые локальные роли
берутся из индекса. У подключённых потребителей читается рабочее дерево.

Срез предлагает проверить связанные места и показывает число участков кода
без меток. Такой участок состоит из соседних изменённых строк без разрешённой
цели. Правки Markdown вне областей явных якорей считаются отдельно. Для
каждого фрагмента диффа в обоих случаях берётся большее из двух чисел
участков по сторонам, поэтому замена учитывается один раз.

Сводка считается до обрезки. A4 и T3 остаются обычными сигналами. Проверка
устаревания использует текущие связанные места и общие
[пределы](slice.md#staleness). При пустом диффе или отсутствии связанных
мест код возврата 0. При отсутствии Git, неверной базе или ошибке чтения
диффа код возврата 2.

Действующая [отметка просмотра](review.md) снимает A4 своей пары и сохраняет
охват проверки. Сам T2 отметками не подавляется.

## Выдержки разделов <a id="excerpts"></a>

В тексте блок «Изменённые разделы» идёт после сигналов и правил, перед
понятиями. В нём показана формулировка до и после правки, в том числе
для разделов без связанных мест. Все разделы и обе стороны делят
`max(1, slice_budget // 3)` строк в пределах [общего бюджета](slice-output.md#budget).
Чтобы посмотреть выдержки и сигналы, используйте `--only excerpt`.
Список `--only` без `excerpt` скрывает выдержки. `--full` выводит их
целиком вне бюджета.

## JSON <a id="json"></a>

Схема остаётся 1. `target.kind` — `diff`, `target.target` — `--diff BASE`
или `--staged`. Общие поля, включая `repo` и метаданные источников при
подключениях, описаны в [схеме обычного среза](slice-output.md#json).

У каждого элемента `entry`, `code` и `tests` есть `matched_targets` со
всеми различными целями, общими для меток места и диффа, даже если цель
одна. Канонические адреса, включая префиксы подключений у внешних целей,
отсортированы лексикографически по полному адресу. Строка `via` в `entry`
и `code` равна первой цели, `matched_targets[0]`. При выводе ролей
`target_roles` перечисляет совпавшие якоря с их ролями. Фильтр выбирает
места целиком, сохраняя основания их появления.

Для допустимых правок Markdown `checks.diff.unanchored` считает участки вне
областей явных якорей. У каждого показанного элемента `checks.diff.sections`
есть адрес `target` и текст `before` и `after`. Значение `null` означает,
что на этой стороне раздела нет. Поле `linked: false` появляется, если
связанных мест не было до фильтрации вывода. Если часть строк раздела
обрезана, в `omitted` указано их число для `before` и `after`. Если
обрезаны все строки одной стороны, там будет пустая строка. Если из-за
предела целиком скрыты разделы, их число указано в `checks.diff.sections_omitted`.
При обрезке любого из этих видов `incomplete` равно `true`.

У места в коде или тестах `reasons` связывает цель с основанием: `contract-change`
для правки раздела, `target-removed` для удалённой цели, `decision-number`
для метки на изменённое решение по номеру, `code-change` для правки кода.
Для связи с договором `link` описывает судьбу самой метки. Например, у теста,
который всё ещё ссылается на удалённый якорь, будет `target-removed` и `retained`.
У снятой метки будет `removed`, у добавленной — `added`. Если место доступно
только на прежней стороне, `side: "before"` указывает, откуда взяты путь и строка.

```json
{"checks": {"diff": {"mode": "diff", "base": "HEAD", "files": 2, "unmarked": 1}}}
```

`files` считает затронутые файлы кода, включая переименования без правки
строк, а `unmarked` — участки кода без разрешённой цели. Для `--staged`
значение `mode` равно `staged`, а `base` равно `null`.
`cross-repo-staleness` считает каждое место с межрепозиторной связью один
раз до фильтрации. Сообщения `diff-review`, `diff-unmarked` и, при правках
вне якорей, `diff-unanchored` сохраняются в `notes` при любом `--only`.
Ошибка чтения: `{"schema": 1, "error": "invalid-diff", "message": "…"}`.
Неверное сочетание аргументов даёт обычное сообщение CLI с кодом 2.

При наличии `reviews.json` поле `summary.reviewed_pairs` считает снятые пары
A4 до обрезки и `--only`, как у [обычного среза](review.md#summary).

## Одновременная правка описания и кода <a id="mixed-example"></a>

В `docs/export.md` замените якорь `#row` на `#record`, а требование писать
имя перед идентификатором — требованием писать идентификатор перед именем.
Перенаправьте метку функции `write_row` в `src/export.py` на
`docs/export.md#record`. Метка теста `test_read_row` в `tests/test_export.py`
всё ещё ссылается на `docs/export.md#row`.

```bash
lipi slice --diff HEAD
git add docs/export.md src/export.py
lipi slice --staged --format json
```

Оба среза показывают прежнюю формулировку у `docs/export.md#row` и новую
у `docs/export.md#record`. В блоках мест видно, что произошло с каждой связью.

```text
Места в коде
  src/export.py:1  def write_row():  [src] — изменение кода, #record (ссылка добавлена), #row (ссылка убрана)
Места в тестах
  tests/test_export.py:1  def test_read_row(): — #row (ссылка на удалённую цель)
```

В JSON у `#row` значение `after` равно `null`, у `#record` значение `before`
равно `null`. В `reasons` теста будет такой элемент.

```json
{"target": "docs/export.md#row", "reason": "target-removed", "link": "retained"}
```

Отдельная команда `lipi check` выдаёт [T1](codes.md#t1) для метки теста.
См. также [пример диффа только по коду](slice-examples.md#diff).
