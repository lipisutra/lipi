# Срез по диффу

После правки `lipi slice` показывает связанные места, которые стоит
проверить. Связь сама по себе не означает, что код или описание неверны.
Общие блоки, предел, сигналы и схема ответа — в [договоре среза](slice.md).

## Выбор изменений <a id="selection"></a>

```bash
lipi slice --diff HEAD
lipi slice --diff v1.0.0 --format json
lipi slice --staged
```

Нужен ровно один источник: цель, `--diff <база>` или `--staged`.
`--diff` сравнивает отслеживаемые файлы рабочего дерева с одной ревизией
Git, включая подготовленные и неподготовленные изменения. Неотслеживаемые
файлы не входят: сначала добавьте их в индекс. `--staged` сравнивает индекс
с HEAD; до первого коммита — с пустым деревом. Неподготовленные изменения
не влияют на выбор целей этого режима.

Изменения читаются без записи файлов, обновления индекса или запуска
проверок проекта. Не учитываются Markdown, двоичные и исключённые файлы,
каталоги описания, рабочих материалов и решений, слишком большие файлы.
Границы обхода те же, что у меток кода. Чистое переименование без правки
строк не добавляет целей.

На обеих сторонах диффа строка относится к блоку меток до следующего
блока или конца файла. Добавленные строки используют новые метки,
удалённые — прежние, в том числе при удалении самой метки или файла.
Номера и пути целей разрешаются по текущим документам проекта; связи и
показываемые места берутся из рабочего дерева. Срез не восстанавливает
весь проект на прежней ревизии.

## Ответ <a id="response"></a>

Порядок: `signals`, `obey`, `concepts`, `entry`, `code`, `tests`, `context`.
Понятия — все разрешённые цели затронутых меток, включая страницы и номера
работ; у каждой заголовок и число мест в коде. По ним собираются принятые
решения, правила, уточнения и соседи, как в обычном срезе. Другие места
тех же целей и тесты выводятся без изменённых объявлений. Общее понятие,
основание или место не повторяется из-за нескольких изменённых файлов.
При `repos` дифф остаётся местным, а внешние цели и потребители входят
по [договору подключений](slice.md#repos).

Срез предлагает проверить связанные места и показывает число участков без
меток. Место без меток — непрерывный участок изменённых строк без разрешённой
цели. Для каждого фрагмента диффа
считаются участки с обеих сторон, берётся большее из двух чисел: замена
не удваивает счёт. Неизвестная цель тоже не подтверждает связь.

Сводка считает весь собранный срез до обрезки, `checks.diff.unmarked` —
все такие участки. A4 и T3 остаются обычными сигналами, сама связь по
диффу не создаёт предупреждения. Проверка устаревания использует текущие
связанные места и общие [пределы](slice.md#staleness).
`--only`, `--layer`, `--depth`, `--full` и предел строк действуют как
обычно; выдержки у диффа нет. Пустой дифф или отсутствие меток — ответ
с кодом 0. Нет Git, неверная база или ошибка чтения диффа — код 2.

Действующая [отметка просмотра](review.md) снимает A4 своей пары и сохраняет
охват проверки. Сам T2 отметками не подавляется.

## JSON <a id="json"></a>

Схема остаётся 1. `target.kind` — `diff`, `target.target` — `--diff BASE`
или `--staged`. Остальные поля и элементы блоков имеют общую форму,
включая `repo` и метаданные источников при подключениях.
Дополнительное поле:

```json
{"checks": {"diff": {"mode": "diff", "base": "HEAD", "files": 2, "unmarked": 1}}}
```

`files` — число затронутых файлов кода, включая переименования без правки
строк. Для `--staged` значение `mode` — `staged`, `base` — `null`.
Сообщения рядом со сводкой — `notes` с кодами `diff-review` и
`diff-unmarked`; они сохраняются при любом `--only`.
Ошибка чтения: `{"schema": 1, "error": "invalid-diff", "message": "…"}`.
Неверное сочетание аргументов даёт обычное сообщение CLI с кодом 2.

Пример ответа — в [примерах среза](slice-examples.md#diff).

При наличии reviews.json поле `summary.reviewed_pairs` считает снятые пары
A4 до обрезки и `--only`, как у [обычного среза](review.md#summary).
