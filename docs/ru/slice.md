# Срез: `lipi slice`

Срез отвечает на вопрос «что нужно знать, чтобы безопасно начать задачу» по
цели или изменениям кода. Он упорядочен, ограничен по
размеру и честен о неполноте. Здесь — точная форма ответа. Текст — для
человека, JSON — договор с инструментами и агентами.

```bash
lipi slice <цель> [--format json] [--full] [--depth 2|3]
                  [--layer <слой>]... [--only <блок>[,<блок>]]
lipi slice --diff <база> | --staged
```

Срез только читает: не пишет файлов (и `INDEX.md`), не трогает базовую
линию, не запускает проверки проекта. Уровни из `codes` действуют: выключенный
код не даёт сигналов и не считается в сводке.
Режимы изменений и их JSON — в [срезе по диффу](slice-diff.md); флаги вывода общие.

## Цель <a id="target"></a>

| Запись | Вид цели |
| --- | --- |
| `docs/pricing.md#threshold` | раздел (путь от корня проекта) |
| `docs/pricing.md` | страница |
| `ADR-018` | решение (регистр и ведущие нули не важны: `adr-18`) |
| `ISS-007`, `PLN-005`, `DSC-002`, `AUD-001` | работа |
| `src/domain/discount.py` | существующий файл кроме `.md`, с учётом [исключений](map.md#rows) и Git |
| текст без пути и номера | поиск |

Поиск без релевантности: точное имя якоря или номер; иначе подстрока среди
якорей и номеров; иначе подстрока среди заголовков. Одно совпадение — срез
по нему, и в строке цели сказано, как найдено. Ни одного или несколько —
код возврата 1 и до 5 кандидатов в фиксированном порядке: сначала
совпавшие по якорю или номеру, затем по заголовку; внутри — по `target`
(пути по алфавиту, номера по типу и числу). Ничего похожего нет — список
пуст.

Страница без якоря: срез не отказывает, а показывает сигналы по странице и
блок «Понятия» — её якоря с числом мест в коде у каждого.

Заголовок понятия определяется местом якоря: у заголовка Markdown — его
текст; у строки таблицы — текст первой ячейки; у абзаца или пункта — начало
его собственного текста. Якорь и разметка убираются, переносы и пробелы
сворачиваются. Заголовок абзаца или пункта — до 80 знаков по границе слова;
если есть скрытый хвост, добавляется `…`, входящее в эти 80 знаков.
Одно слово длиннее предела обрезается по знакам с `…`.

## Коды возврата <a id="exit"></a>

- **0** — срез получен, в том числе пустой или неполный. Уровни сигналов код не меняют.
- **1** — цель не найдена или неоднозначна; в ответе кандидаты.
- **2** — неверные аргументы, C1 (настройки или файл состояния) либо ошибка диффа Git.

## Блоки <a id="blocks"></a>

При `lipi lang ru` текст выглядит так. В JSON пояснения lipi в `message` и `notes[].text` английские; текст проекта сохраняется.

| Блок | `kind` | Что в нём |
| --- | --- | --- |
| Сигналы | `signals` | устаревание (A4), статус цели, `@trace` и `covers` (T3), открытые работы, T4 подключений |
| Соблюдать | `obey` | принятые решения и разделы `AGENTS.md`/`.agents/` (кроме `.agents/lipi/`) |
| Понятие | `excerpt` | выдержка из самой цели |
| Понятия | `concepts` | разделы, которые реализует файл; якоря страницы |
| С чего начинать | `entry` | места в коде, совпавшие с `entry` |
| Места в коде | `code` | остальные места, по слоям |
| Тесты | `tests` | места в тестах |
| Цели работы | `targets` | на что ссылается работа |
| Контекст | `context` | соседние документы, только заголовками |

Сигналы всегда первыми. Если сама цель больше не действует (решение
«superseded» или «rejected», замечание «closed», план «completed» или
«canceled», обсуждение «closed»), первый сигнал — её статус, код T3, с
преемником у заменённого решения. Сообщение о самой цели: «ISS-015 closed —
срез по истории, не по текущей работе»; для плана — «не по текущему плану»,
для решения — «не по действующему решению». Сообщения меток и `covers`
по-прежнему говорят, что проверить в опирающемся на них коде.
Уровень — из `codes`. Обычные ссылки из описания и правил на заменённое
или отклонённое решение также дают T3 с просьбой проверить актуальность
текста. Решения в каталоге `decisions` доступны и при `"workflow": null`.
Остальное — по виду цели:

| Цель | Порядок после сигналов |
| --- | --- |
| раздел, решение | `obey`, `excerpt`, `entry`, `code`, `tests`, `context` |
| страница | `obey`, `concepts`, `entry`, `code`, `tests`, `context` |
| файл кода | `obey`, `concepts`, `tests`, `code` (другие места тех же понятий), `context` |
| работа | `obey`, `code` (метки на номер), `targets`, `context` |
| дифф | `obey`, `concepts`, `entry`, `code`, `tests`, `context` |

**Что откуда берётся:**

- **Соблюдать** — связь с целью двумя путями, `relation` говорит каким:
  `link` — документ ссылается на цель; `mark` — метка на документ стоит в
  том же блоке меток, что и метка на цель (метки подряд перед одним
  объявлением). Заменённые и отклонённые решения сюда не попадают — они в
  сигналах.
- **Работа:** «Соблюдать» также собирается через цели её прямых ссылок,
  по тем же связям и уточнениям. У каждого основания `via` — список целей,
  через которые оно вошло; для прямой связи с работой — её номер.
  Основание выводится один раз, с заголовком и всеми путями `via`;
  собственные срезы целей не раскрываются. Прямая цель-решение учитывается
  вместе с основаниями и уточнениями, как при запросе этого решения.
- **Уточнения решений** задаёт только строка шапки
  `- Refines: [ADR-NNN](путь.md)`, допускаются повторения. По номеру решения
  в «Соблюдать» входят сама принятая цель, её принятые основания вверх по
  цепи и уточнения вниз. От найденного основания к другим его уточнениям
  обход не переходит. По разделу или файлу кода — связанное решение и его
  уточнения вниз. Обычные ссылки между решениями дают только контекст.
  Ветвь заканчивается на непринятом решении: «proposed» даёт info,
  «superseded» или «rejected» — T3. Циклы не повторяют узлы; связи уточнения
  используют `relation: link` и учитываются до ограничения вывода.
- **Открытая работа по месту** — документ, который ссылается на цель или
  помечен в том же блоке меток, в одном из статусов: замечание «open»,
  «in progress»; план «new», «in progress», «pending acceptance»; обсуждение
  «open»; решение «proposed» — оно может поменять правила этого
  места. Отложенный план, принятое решение (оно в `obey`) и аудит открытой
  работой не считаются. Уровень `info`, `code` — `null`.
- **Место в коде** — файл, строка метки, имя объявления: первая строка
  после блока меток без пустоты и комментария. Строки, начинающиеся после
  отступа с `#`, `//`, `/*`, `*`, `--`, `;` или `<!--`, пропускаются. Поиск идёт
  до следующего блока меток или конца файла; нет объявления — пустое имя.
  Для метки в конце строки кода берётся сама эта строка. Имя обрезается
  до 80 знаков. Слой — по `layers`, без настройки — каталог верхнего уровня.
- **Тест** — место в файле слоя `tests` или по шаблонам имён (`tests` в
  [settings.md](settings.md)).
- **Понятия** — разделы, на которые ведут метки файла (у файла кода), или
  якоря страницы (у страницы); у каждого число мест в коде по всему
  проекту.
- **Общий код** соседей не порождает. Файл, который реализует много
  понятий, показывает их в `concepts` в пределах предела; скрытое
  называется «реализует ещё N понятий».
- **Глубина** 1: соседи — документы, связанные с целью явной ссылкой в
  любую сторону; у работы — документы, которые ссылаются на неё.
  У раздела учитываются ссылки именно на раздел и из него; ссылка на
  страницу целиком относится к цели-странице. `--depth 2|3` добавляет
  соседей соседей, тоже заголовками. Весь [комплект указателей](workflow.md#files)
  и `<workflow>/masterplan.md`, включая их якоря, не входят в соседей и не
  используются для перехода к следующим соседям; прямой запрос разрешён.

**Порядок внутри блока:** сигналы — T3 самой цели, затем `error`,
`warning`, `info`, затем путь и строка; места — слои в порядке `layers` (без настройки — по алфавиту),
затем путь и строка; документы — решения по номеру, затем пути по алфавиту.

## Сводка <a id="summary"></a>

Первая строка после строки цели; нулевые части не выводятся; порядок
частей фиксирован: ошибки, предупреждения, решения, правила, понятия,
точки входа, места в коде (слои), тесты, открытые работы, цели работы.

```text
2 предупреждения · 1 решение · 1 правило · 2 точки входа · 11 мест в коде (4 слоя) · 6 тестов · 1 открытая работа
```

В JSON те же части — ключи `errors`, `warnings`, `decisions`, `rules`,
`concepts`, `entry`, `code`, `layers`, `tests`, `open_work`, `targets`;
нулевые ключи присутствуют; при подключениях добавлен `repos` — число
репозиториев с нетестовыми местами, а `layers` считает пары «репозиторий, слой».

`decisions` и `rules` считают основания в «Соблюдать» один раз,
в том числе найденные через несколько целей работы.

«Мест в коде» — все места, включая точки входа, без тестов. Сводка считает
весь срез до обрезки, но A4 — только подтверждённые сигналы из проверенной
части. Объём проверки устаревания указан отдельно и не зависит от обрезки.

## Проверка устаревания <a id="staleness"></a>

A4: отбор по истории, затем blame до 64 файлов без `-C` и 16 с `-C`.
Непроверенное не становится сигналом; незакоммиченные правки одновременны.
`checks.staleness`: `state`, `checked`, `total`; аудит полный.
[Границы и порядок](slice-output.md#staleness), [просмотр A4](review.md#summary).

## Предел <a id="budget"></a>

Один предел строк для text и JSON: серьёзным сигналам — первая половина,
затем каждому блоку до трёх строк, остаток — по порядку ответа. Выдержка
занимает не больше трети; `--full` выводит её вне предела. Сводка считается
до обрезки, сигналы сохраняются при `--only`. Точные единицы, сокращение
выдержки и флаги — в [правилах отбора](slice-output.md#budget).

## Подключённые репозитории <a id="repos"></a>

Поля подключений появляются только с `repos`; метаданные общие с
[картой](map.md#repos). Счётчик просмотренных пар относится только к своему репозиторию.

### Цели и связи

- Без префикса запрос и поиск локальные. Внешние цели: `core::docs/api.md#request`,
  `core::docs/api.md`, `core::ADR-018`; поиск `core::request` — среди разрешённых целей.
  Без `lipi.json` у соседа допустим только `путь#якорь`, без поиска и обратных связей.
  Внешние файлы кода, работы кроме решений и правила исполнителя не поддерживаются.
- Неизвестное подключение, отсутствующая или запрещённая цель — код 1,
  `error: not-found`, `message` с причиной; неоднозначность — `ambiguous`.
  Причина есть и у отказа по номеру работы или поисковому запросу.
  Кандидаты имеют `repo`. Неверный запуск или C1 своего проекта — код 2.
- Недоступное известное подключение — код 0, `incomplete: true`. В `target`
  сохраняются `repo` и запрос без префикса; `title` пуст, `found` отсутствует.
  `kind` определяется формой запроса, для поиска — `null`; наличие цели не утверждается.
- Выдержка и контекст внешней цели — из разрешённых областей её репозитория;
  код и тесты — из своего. У своего понятия обратный поиск добавляет места
  соседей: `code` разрешает обычный код, `tests` — тесты по настройкам соседа.
  Его ссылка на нас распознаётся по физическому корню, независимо от имени.
  Третьи репозитории, чужие работы и правила не читаются, даже для контекста.
- «Соблюдать» сохраняет местные правила. Внешнее принятое решение входит
  по прямой метке своего кода на номер, вместе с принятыми уточнениями
  из того же соседа по обычному правилу решений. Чтение требует `decisions`,
  к третьим репозиториям не переходит. Условие метки относится к «Соблюдать».
- Срез местного файла учитывает внешние метки. `--diff`/`--staged` читают
  изменения только своего дерева; внешние цели и обратные связи — как выше.

### Адреса, порядок и счётчики

У цели, кандидата и адресуемого элемента есть `repo`: `null` для своего,
иначе имя подключения. `path` и `target` — без префикса; идентичность —
`(repo, target)` или `(repo, path, line)`. **У сигнала** `repo` — владелец
`path`, а без `path` — владелец цели; обязательный `target_repo` отдельно
задаёт владельца `target`. Например, местный T3 на внешнее решение:
`{"repo":null,"path":"src/client.py","line":2,"target_repo":"core","target":"ADR-018"}`.
В тексте адреса квалифицированы: `core::ADR-018`. `via` сохраняет тип
и канонические метки относительно запускающего проекта, включая префиксы.

Блоки — в прежнем порядке; внутри своё, затем подключения в порядке `repos`,
далее прежние слои, пути и номера. Сигналы: сначала T3 самой цели, затем
серьёзность, источник, путь и строка. `layer` элемента — без префикса;
`--layer` выбирает полное имя: свой слой или `<подключение>::<слой>`.
В режиме подключений имя слоя не содержит `::` — иначе C1; без `repos` имена прежние.
Предел общий. Сводка и `code_count` считают места в доступном охвате. `--only` не скрывает сведения об источниках.

### Состояние и неполнота

`checks.repos` — массив: свой источник, затем все подключения по настройке.
Объект: `repo`, `state` (`ok`/`unavailable`/`no-git`), `head` (SHA репозитория
или `null`), `dirty` (staged, unstaged и неигнорируемые untracked репозитория;
неизвестно — `null`), `reason` (причина недоступности/нет Git, иначе `null`),
`read` (список из настройки). У своего `repo: null`, `read` содержит
`docs`, `decisions`, `code`, `tests`; локальные права от этого не меняются.
Метаданные всех подключений читаются один раз, даже если их код не нужен.
`no-git` читаем; до первого коммита возможны `ok`, `head: null`, известный `dirty`.

Нечитаемая цель: `unavailable`, `head`/`dirty` — `null`. Все данные источника,
даже ранее прочитанные, исключаются; местные сохраняются. У запроса его цели
остаётся только T4, если включён. Ответ не зависит от порядка чтения.
Верхний `reproducible` истинен, только если все источники `ok`, HEAD известен
и `dirty: false`. Грязное дерево, отсутствие Git или HEAD сами по себе
не дают `incomplete`; недоступность, обрезка и частичная местная A4 дают.

T4 — один сигнал на недоступное подключение: `repo`, `target_repo` и `target`
равны его имени (здесь цель — подключение), `code: T4`, `level` из `codes`,
`message` с причиной. Уровень не меняет код возврата среза и карты;
у `lipi check` T4 уровня `error` даёт код 1. `off` убирает лишь сигнал,
сохраняя `unavailable`, `incomplete: true`, `reproducible: false` и охват.
В тексте названы источники, HEAD (достаточно 7 знаков) и их состояние.
В JSON — `notes` формы `{code, text}`: `repos-scope` (найдено среди перечисленных
и доступных), `repos-incomplete` (непрочитанное), `repos-unreproducible` (dirty/нет Git/HEAD).
Это служебные строки вне предела, как и пометка `cross-repo-staleness`:
«межрепозиторное устаревание не проверено», сохраняемая при любом `--only`.
`checks.staleness` учитывает лишь местные связи к местным разделам и получает
`scope: local`. Исключение межрепозиторных связей само не даёт `incomplete`.
Примеры внешней цели, грязного и недоступного соседа — в
[примерах подключений](slice-examples.md#repos).
