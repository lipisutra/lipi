# Найти документ по тексту

## От вопроса к срезу <a id="command"></a>

Если известен адрес раздела, откройте его через `lipi slice`. Если вопрос
дал промах при [обычном поиске цели](slice.md#target), запустите предложенную
команду с `--search`, чтобы поискать те же слова в заголовках и абзацах.

```bash
lipi slice 'Сколько дней хранится копия?'
lipi slice --search 'Сколько дней хранится копия?'
lipi slice docs/storage.md#cleanup
```

Например, раздел может называться «Политика очистки», а в тексте окажется
фраза «Копия хранится 30 дней». Перед открытием раздела прочитайте выдержку.
Даже единственный кандидат может описывать другой вид копии.

## Где искать <a id="scope"></a>

Запрос без префикса ищет в доступных Markdown-страницах своего репозитория.
Для поиска в одном прямом подключении укажите его имя из настроек.

```bash
lipi slice --search 'library::Сколько дней хранится копия?'
```

Доступные страницы определяют [области чтения и каталоги подключения](settings.md#repos).
Для поиска по тексту у соседа нужен собственный `lipi.json`. В локальной
выдаче есть подсказки поиска у соседей, даже если нашлись местные кандидаты.
Каждая команда ищет только в выбранном репозитории.

## Порядок совпадений <a id="match"></a>

Регистр букв не влияет на совпадение. Короткие термины, например `НДС`,
сопоставляются целиком. Для длинных слов допустимо изменение одной буквы
в конце при общем начале длиной от четырёх букв. Так по слову «копию»
можно найти «копия». Для `copies` и `copy` попробуйте другую форму.

Вес каждого слова запроса зависит от его частоты среди страниц, где есть
хотя бы одно совпадение. Несколько разных слов в одном абзаце могут вместе
перевесить одно редкое слово. Редкий термин вроде `API` по-прежнему может
перевесить несколько слов, общих для большинства найденных страниц. Повторы
слова на странице не увеличивают вес. В области из одной страницы совпадение
сохраняет вес. При прочих равных точное совпадение стоит выше. Для каждого
адреса выдаётся одна лучшая выдержка.

## Как открыть результат <a id="output"></a>

В списке до пяти кандидатов и общее число найденных. По адресу цели откройте
срез, а по `файл:строка` перейдите в редакторе к совпавшим словам.
Если выдержка вне области явного якоря, адрес ведёт на страницу целиком.

Для работы с JSON укажите `--format json`. В ответе схемы 1 есть `query`,
`total` и `candidates` в порядке выдачи. Пример одного кандидата:

```json
{"repo":null,"target":"docs/storage.md#cleanup","title":"Политика очистки","excerpt":"Копия хранится 30 дней.","file":"docs/storage.md","line":12}
```

Для соседа добавьте к `target` префикс `имя::` из поля `repo`. Путь для
редактора считается от каталога запуска. В Windows на разных дисках путь
абсолютный. Строки отсчитываются с 1. При запуске из подкаталога показанный
путь приведёт к тому же файлу и строке.

При промахе обычного текстового запроса команда для поиска приходит в JSON
в поле `search_command`. Локальный запрос с `--search` также может вернуть
`suggestions` для поиска у соседей. Для прочитанного источника код 0
означает наличие кандидата, код 1 — отсутствие совпадений. Для недоступного
подключения возвращаются код 0 и `incomplete: true`. Неверные аргументы
или настройки дают код 2.
