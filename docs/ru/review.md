# Просмотр предупреждения об устаревании

`lipi review` сохраняет результат просмотра одной пары A4.
[Примеры](review-examples.md), [все команды](commands.md).

## Пара и область <a id="pair"></a>

Допустимы только местные связи, для которых вычислен A4:

| `relation` | `source` | `target` |
| --- | --- | --- |
| `trace` | область группы меток в файле кода или тестов | явный якорь Markdown |

Отметка применима к A4 для метки `@trace` на местный Markdown-якорь.
При выборе пары действуют общие правила обхода и разрешения целей.

Группа trace — максимальная последовательность соседних физических строк
с активными отдельными метками; строка с кодом и меткой образует свою группу.
Несколько меток на одной строке дают одну группу, повтор цели — одно ребро.
Неразрешённая активная метка остаётся границей; `ignore-trace` границей не
является. Область включает группу и текст до следующей группы или EOF.
Для даты A4 начальные отдельные комментарии меток исключаются, а код рядом
с inline-меткой учитывается. Для отпечатка включаются все строки области.

Markdown использует общую область якоря: у таблицы это шапка и выбранная
строка, без соседних строк между ними.

## Рабочее дерево <a id="worktree"></a>

Для применения отметок реестр и обе области читаются из рабочего дерева.
`audit --reviews-since` отдельно читает прежний реестр из Git для сравнения.
T2 не учитывает отметки; `review --staged/--diff` не поддерживаются.
`slice --staged/--diff` по-прежнему выбирает цели по Git, но его A4
проверяет рабочее дерево. Нет истории — нет подтверждённого A4.

## Отпечатки и идентичность <a id="fingerprints"></a>

Алгоритм `sha256-lines-v1`:

1. Прочитать UTF-8; заменить CRLF и одиночный CR на LF. По LF разделить на
   строки, сохранив завершающий LF в строке; после последнего LF не добавлять
   пустой элемент. Другие Unicode-разделители остаются символами.
2. Взять точный упорядоченный набор строк области, без абсолютных номеров
   и расстояний между разрывными фрагментами. Не удалять пробелы, комментарии,
   метки, пустые строки и признак конца последней строки.
3. Хэшировать UTF-8 канонического JSON массива
   `["sha256-lines-v1", kind, lines]`, где `kind` — `trace` или `anchor`.

Канонический JSON здесь: ключи объектов по возрастанию, без пробелов между
элементами, Unicode непосредственно в UTF-8, стандартное экранирование
управляющих символов, `"` и `\`; `/` не экранируется. Эквивалент stdlib:
`json.dumps(value, ensure_ascii=False, sort_keys=True, separators=(',', ':'), allow_nan=False)`.
Непарные суррогаты не допускаются. Хэши — 64 строчные hex-цифры SHA-256.

`id` записи — SHA-256 канонического массива
`["review-pair-v1", relation, source, target]`. Обе структуры включают свои
отпечатки. Автор, время, HEAD и показанные координаты в id не входят.
Это ключ пары состояний, а не вечный ID объявления.

Для trace в указанном файле ищутся все группы с нужным активным ребром
и отпечатком source. Должна найтись ровно одна, а target также должен
разрешиться однозначно и совпасть по отпечатку. Две одинаковые группы
запрещают создание и применение записи; номер строки не устраняет эту
неоднозначность сохранённого состояния.

Сдвиг строк вне областей и посторонний commit отметку сохраняют. Единственная
неизменённая группа, перемещённая внутри файла, считается тем же состоянием.
Поиск перемещений между файлами, похожего текста и символов не выполняется.
Удаление/смена связи или якоря отменяет применимость. Переносы через lipi
сохраняют её по правилам ниже; ручное переименование — нет. Точная обратная
правка может восстановить её до prune. Разные версии пары могут храниться
одновременно; устаревшие версии видны в плане уборки.

## Файл `.agents/lipi/reviews.json` <a id="state"></a>

Обязательные поля верхнего уровня: `schema: 1`,
`algorithm: "sha256-lines-v1"`, `entries` — массив. Пустой массив допустим.

| Поле записи | Тип и значение |
| --- | --- |
| `id` | хэш пары по алгоритму выше |
| `relation` | `trace` |
| `source`, `target` | дескрипторы обеих сторон, см. ниже |
| `reviewer` | непустая строка, явно переданная через `--by` |
| `reviewed_at` | время записи, UTC `YYYY-MM-DDTHH:MM:SSZ`, реальная дата |
| `reason` | непустая строка с объяснением результата просмотра |
| `head` | HEAD при просмотре: полный Git OID (40/64 строчные hex-цифры) или null |

Дескриптор trace: `{"kind":"trace","path":"src/a.py","sha256":"…"}`.
Дескриптор anchor: `{"kind":"anchor","path":"docs/a.md","anchor":"rule","sha256":"…"}`.
Многоточия здесь обозначают тип, не допустимые значения; полный валидный
пример — в приложении. Номер строки, ordinal и symbol в файле не хранятся.
Source всегда имеет kind `trace`, target — `anchor`. Поле relation
сохраняется для расширения schema 1. Другие значения дают C1.
Автор обязан объяснить, почему описание осталось верным, а не писать «OK».
Команда проверяет непустоту после удаления краевых пробелов, но не оценивает
смысл объяснения; то же правило непустоты применяется к reviewer.

Пути — канонические POSIX-пути файлов от корня проекта, без начального `/`,
диска, `\`, NUL, пустых сегментов, `.` и `..`; anchor — точный ID, без `#`.
HEAD справочный, не условие совпадения; воспроизводимость всего дерева
по нему не утверждается. Снимков индекса и диапазонов в формате нет.

C1 и код 2: некорректный JSON/UTF-8, повтор JSON-ключа, неизвестное поле,
версия/алгоритм/отношение, неверный тип (в том числе bool вместо schema),
несовместимые виды сторон, неверные путь/хэш/id/дата/OID, пустой автор или
причина, повтор id, существующий нечитаемый файл. Проверяется весь файл:
плохую запись нельзя молча пропустить. Несуществующая область или другой
отпечаток — не C1: это состояние записи, а не повреждение её формы.

Файла нет — пустой реестр. Он не входит в `lipi.lock.files`, не является
шаблоном и сохраняется при init. Команда записи создаёт его по необходимости.
Запись UTF-8 с LF, отступ 2, сортированные ключи и entries по id; финальный LF.
Точная повторная отметка — no-op: автор, дата и объяснение не перезаписываются.

## Выбор и подтверждение <a id="confirm"></a>

```text
lipi review TARGET --at PATH[:LINE] [--full] [--format json]
```

Текст предпросмотра и отказа следует языку интерфейса; машинный ответ описан в [JSON](#json).

TARGET — точный местный `путь#якорь`.
`--at` выбирает группу кода по пути и, если задан, положительному номеру
строки внутри неё. Суффикс после последнего `:` — номер; пути от корня.
Поиск по словам, wildcard, выбор всего файла или всей цели не поддерживаются.

Выбор делается среди структурных пар, до фильтрации по давности. Поэтому
два места одного файла на одну цель неоднозначны и тогда, когда A4 сейчас
есть лишь у одного. Возвращаются варианты с путём, координатами и целями;
записи нет. Строка уточняет группу, но не разрешает дубликаты идентичности.

Выбранная пара должна давать A4 до применения отметок.
Уже просмотренная пара также допустима; выключенный код не создаёт кандидата.

Первый вызов только показывает: код/уровень, отношение, обе стороны,
точные диапазоны и первые 20 выбранных строк каждой стороны, число
непоказанных строк, отпечатки, HEAD, существующую отметку и token.
`--full` показывает все выбранные строки обеих сторон, token тот же.
Причину вместо исполнителя команда не придумывает.

Подтверждение — та же команда плюс:

```text
--confirm TOKEN --by ACTOR --reason TEXT
```

Второй вызов заново читает рабочее дерево, выбирает пару и сверяет token. Указанные
файлы/области и реестр должны соответствовать показанному состоянию.
Token — непрозрачная контрольная строка SHA-256: пара, HEAD, содержимое
сторон, влияющие на выбор настройки и байты реестра (отсутствие отличается
от реестра с пустым `entries`). Это привязка подтверждения,
не credential. Непустые `--by`/`--reason` обязательны; автор не берётся
автоматически из git config. Интерактивного вопроса и общего `--yes` нет.

Гонка даёт `changed-preview`, код 2, без записи: нужен новый preview.
При работе с файлами проверяется стабильность чтения.
Запись реестра сериализуется, проверяет его прежние байты и выполняется
атомарной заменой. Проект целиком не блокируется: последующая правка любой
стороны делает записанное состояние неприменимым. Check/audit/slice не
создают и не меняют реестр; существующее обновление INDEX остаётся прежним.

Успех preview/записи/no-op — 0. Неверные аргументы, отсутствие кандидата,
неоднозначность, C1, ошибка записи или изменившийся preview
— 2. Код 1 новой команде не нужен. Текст и JSON различаются только формой.

## JSON новой команды <a id="json"></a>

Служебный текст `message` в JSON всегда английский. Выдержки, имена авторов и объяснения сохраняют язык источника.

| Операция | Обязательные поля помимо `schema: 1`, `operation: "review"` |
| --- | --- |
| preview | `result:"preview"`, `pair` (id/relation/source/target), `code`, `level`, `source_view`, `target_view`, `head`, `existing` (id или null), `token` |
| запись/no-op | `result:"written"` или `"unchanged"`, `file`, `entry` (полная запись) |
| отказ | `error`, `message`; у неоднозначности также `candidates` |

View содержит `ranges:[[first,last],…]`, `lines:["raw line\n",…]`,
`omitted:N`. Диапазоны описывают всю область, lines — первые 20 выбранных
строк или все при `--full`; номера справочные. Candidate содержит
`relation`, `source`, `target`, `source_ranges`, `target_ranges`; если
одинаковый id повторяется у разных групп, диапазоны различают варианты.
`level` — строго `error` или `warning`, после настройки кодов.

Ошибки `invalid-arguments`, `no-candidate`, `ambiguous`, `unavailable`,
`changed-preview`, `write-failed` используют эту форму и код 2.
C1 использует действующую форму JSON чекера с `errors:[{"code":"C1",…}]`.
Ни ошибка, ни preview не создают файл. JSON-примеры — в приложении.

## Применение и сводка <a id="summary"></a>

Строгая валидация файла предшествует проверкам. Для каждой подтверждённой
пары A4 сравниваются оба отпечатка и существование ребра, затем из
кандидатов удаляются только совпавшие пары. После этого формируются
находки, применяется уровень и базовая линия. Код off не учитывается
как снятый; error и `--strict` не обходят результат просмотра.
`--no-baseline` отметки не выключает. Общий граф связей и цепочки T2
в `--structure` не меняются.

При отсутствии файла ответы check/audit/slice сохраняют прежние поля.
При наличии файла к `summary` добавляются:

| Поле | Где | Значение |
| --- | --- | --- |
| `reviewed_pairs` | check, audit, slice | уникальные пары, снявшие активный A4 в этом ответе |
| `reviewed_obsolete` | audit | доказанно устаревшие записи в полном текущем дереве |
| `reviewed_unchecked` | audit | записи, состояние которых не удалось установить |
| `reviewed_by` | audit | авторы учтённых пар, число и время последней отметки |

Одна пара считается один раз; другие места на ту же цель остаются
независимыми. Обычный check A4 не запускает: его счётчик равен нулю,
а существующая проверка T2 не меняется.
В text и GitHub справочные строки следуют языку интерфейса. При `lipi lang ru`, включая нули: «просмотрено
пар устаревания: N»; в аудите дополнительно «устаревших отметок: M;
не удалось проверить: K». Это не findings/annotations и не причина кода 1.
Старые errors/warnings считают только оставшиеся находки; schema остаётся 1.

Срез считает пары всего выбранного среза до budget/only, но только после
фактического подтверждения A4. Отметка не запускает дополнительные blame
сверх прежнего предела и не меняет `checks.staleness`, checked/total,
partial/no-git или incomplete. Нет истории — нет подтверждённого A4 и нет
применённой отметки. Отсутствие сигнала не выдаётся за просмотр.

## Авторы отметок <a id="authors"></a>

`audit --reviews-since <ревизия>` добавляет `summary.reviews_since`: новые

## Перенос вместе с файлами <a id="move"></a>

`lipi mv` включает реестр в общий план. Ручной перенос этого не делает. Реестра нет — создавать его
не нужно; повреждение существующего — C1 до записи.

Переносится действующая пара: до операции однозначно найдены обе стороны,
совпали оба отпечатка и существует ребро. Текущий A4 для этого не нужен,
blame не запускается. Учитываются пути и все адресные замены внутри обеих
областей, даже если сами файлы записи остаются на месте.

В планируемом дереве заново выделяются области. Их строки должны точно
совпасть с прежними выбранными фрагментами после адресных замен плана;
сохраняются порядок и границы, не добавляется соседний текст, группа не
делится и не сливается с другой. Обе стороны и связь снова однозначны.
Тогда заменяются пути, нужные SHA и id; reviewer, reviewed_at, reason и
head исходного просмотра остаются. Старая запись заменяется, копии нет.

План показывает old id → new id, адреса и изменившиеся стороны. Не удалось
доказать преобразование действующей затронутой пары или возникла коллизия
id — отказ до записи. Ранее устаревшие/непроверяемые записи не обновляются
и не удаляются; отчёт перечисляет их отдельно. Это не новый просмотр.

Применение повторно проверяет исходные байты и однозначность областей.
Реестр — участник того же отката при ошибке или KeyboardInterrupt.
При массовом переносе затрагиваемый реестр должен быть
чистым в дереве и индексе, как остальные затронутые файлы. Одиночный mv
сохраняет допустимость прежних правок пользователя и откатывает к этим
байтам, а не к HEAD; автоматически реестр не индексирует. Остальные
обновления правил/содержания init не входят в разрешённые адресные замены.

## Уборка <a id="prune"></a>

```text
lipi review --prune [--format json]
lipi review --prune --confirm TOKEN [--format json]
```

Полный план относительно рабочего дерева; несовместим с выбором пары,
`--full`, `--by`, `--reason`. Удаляются только записи,
чья связь/сторона доказанно исчезла или чьё прежнее состояние больше не
совпадает ни с одной допустимой парой. Неоднозначность, ошибка чтения,
исключение настройки, неполный обход и неизвестное состояние сохраняют запись.
Нет A4 по времени, off или непопадание в срез не доказывают
устаревание. Оно считается по области, а не по нынешнему списку находок.

Preview перечисляет id, обе стороны и причину каждого удаления, а также
непроверяемые записи; token связывает весь план и реестр. Подтверждение
повторяет проверку и атомарно удаляет ровно показанное. Реестр не удаляется,
после удаления всех entries остаётся пустой массив. Нет файла/удалений —
no-op, файл не создаётся и не переформатируется, token в preview равен null.

JSON: `schema:1`, `operation:"prune"`, `result:"preview"`, `file`,
`basis:"worktree"`, `remove` и `unchecked` (объекты с `id`, `source`,
`target`, `reason`), `token`.
Reason — `changed`, `missing-source`,
`missing-target`, `missing-relation`, либо `ambiguous`, `unreadable`,
`excluded` для unchecked. Запись: `result:"written"|"unchanged"`, `file`,
`removed:N`, `remaining:M`, `unchecked:K`. Отказы имеют те же error/message
и коды, что review, но `operation:"prune"`; форма C1 чекера остаётся общей.

История удалённых записей остаётся в Git.
