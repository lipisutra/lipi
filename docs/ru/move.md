# Перенос страниц и каталогов

`lipi mv` переносит файлы своего проекта в Git и исправляет их связи.
Вложенный проект определяется ближайшим `lipi.json` от текущего каталога;
без него корнем служит корень Git. Другие каталоги того же рабочего дерева
в план изменений не входят.
Якоря и смысл страниц сохраняются. Деление страницы и распределение её
якорей между новыми страницами остаются задачей автора.

## Формы команды и пути <a id="paths"></a>

```bash
lipi mv docs/old.md docs/reference/new.md
lipi mv docs docs/ru
lipi mv --from moves.txt
```

Без `--apply` команда показывает общий план без записи. Для применения
повторите тот же вызов с `--apply`. `lipi help mv` показывает справку.

Позиционные пути, включая путь к файлу `--from`, считаются от текущего
каталога. Пути **внутри списка** считаются от корня Git-репозитория.
В строке списка — ровно два пути, разделённые пробельными символами.
Кавычки и экранирование разбираются по правилам оболочки, без выполнения
команд, подстановки переменных или раскрытия масок. Пустые строки и
комментарии `#` вне кавычек пропускаются; `#` внутри кавычек — часть пути.
Сам список — явный вход команды: он читается независимо от Git-отбора.

Пример `moves.txt`:

```text
# Пути от корня Git-репозитория
"docs/old page.md" "docs/reference/page.md"
docs/guide docs/ru/guide
docs/logo.svg assets/logo.svg
```

План также показывает [перенос отметок просмотра](#reviews) из состояния проекта.

## Состав переноса <a id="scope"></a>

Одиночный файл в позиционной форме должен быть отслеживаемой Git
Markdown-страницей. Каталог разворачивается в список всех допустимых
отслеживаемых файлов с сохранением структуры: изображения и прочие
файлы включаются независимо от наличия ссылок на них. В `--from` можно
перечислить каталоги и отдельные отслеживаемые файлы, включая изображения.

Перенос каталога внутрь себя, например `docs → docs/ru`, разрешён.
Сначала фиксируется исходный набор файлов, затем вычисляются новые пути;
создаваемое назначение повторно в обход не попадает.

Неотслеживаемые файлы и файлы из исключённых областей остаются на месте;
команда называет их в отчёте, кроме игнорируемых Git. Исключены `skip_dirs`, служебные каталоги,
управляемые файлы lipi, `history/` и подключённые репозитории. Отчёт упоминает архив,
только если он существует. Символьные ссылки не переносятся и не используются
для выхода за границы своего проекта. В `skip_dirs` имя исключает
одноимённые каталоги везде, запись с `/` — путь от корня проекта.
Входящие связи читаются по [общему отбору файлов](checking.md): игнорируемое
Git не читается. Новый неигнорируемый файл со ссылкой участвует в плане;
для каталога и списка переносов сохраняется требование [чистоты](#plan).

## Исправление связей <a id="links"></a>

Из всех исходных и новых адресов строится одна таблица; каждый файл проекта
разбирается на связи один раз. Для ссылки вычисляются оба новых адреса —
страницы, содержащей ссылку, и её цели.
Игнорируемые пути не участвуют и когда переносимая страница на них ссылается.

- Входящие Markdown-ссылки из описания, рабочих материалов и собственных
  правил получают новый адрес цели. Это касается и изображений, и HTML `img[src]` и `a[href]`.
  Меняется только адрес. Примеры кода и HTML-комментарии пропускаются.
- Относительная ссылка между файлами, переезжающими вместе с сохранением
  структуры, остаётся прежней.
- Ссылка из переносимой страницы наружу пересчитывается: `../README.md`
  из `docs/page.md` после `docs → docs/ru` становится `../../README.md`.
- Пути в `@trace` и `covers` идут от корня; они меняются и внутри
  переносимого каталога. Строки с `lipi: ignore-trace` сохраняются как примеры
  и не учитываются в отчёте о метках соседей. Номера работ и внешние цели `имя::цель` сохраняются.
- Примеры в Markdown-коде, строковые литералы и произвольные пути в
  настройках сборки не переписываются. Их адаптирует автор переноса.

В закрытых обсуждениях меняются только адреса связей, текст и смысл
остаются прежними. Соседи с разрешением `code` или `tests` не меняются:
отчёт называет страницы и число найденных строк с метками, которые надо
поправить там. Неизвестные внешние ссылки команда обнаружить не может.

## Проверка плана <a id="plan"></a>

План содержит все переносы, точные замены по файлам и строкам и пропуски.
До записи отклоняются:

- отсутствующий, неотслеживаемый или недопустимый источник;
- повторный источник, пересекающиеся исходные каталоги или файл,
  включённый также через перенос его каталога;
- совпадение источника и назначения, два переноса в одно место,
  конфликт файла и каталога назначения;
- занятое назначение, в том числе отслеживаемый файл, удалённый из
  рабочего дерева: цепочки и обмены занятыми адресами не выполняются;
- пути вне своего проекта, исключённые области, символьные ссылки;
- конфликт Git, недоступность записи, изменение затронутого файла или
  индекса после составления плана.

Для каталога и `--from` все затрагиваемые файлы — переносимые и те, где
меняются связи, — должны совпадать с закоммиченным состоянием и в рабочем
дереве, и в индексе. Иначе команда отказывает и перечисляет эти файлы.
Это относится и к списку из одной пары. Незатронутые файлы могут содержать
любые локальные изменения, включая подготовленные к коммиту.

Чистота определяется содержимым и режимом файла, с учётом преобразований
Git для данного пути, включая окончания строк. Изменение только файловых
метаданных после отката не считается правкой даже у бинарного файла.
Проверка не обновляет настоящий индекс Git.

При одиночном переносе Markdown-страницы сохраняются локальные правки
переносимого файла и файлов со ссылками.

Проверка плана охватывает также [реестр просмотров](#reviews): порча — C1;
невозможность сохранить затронутую действующую отметку — отказ до записи.
Устаревшие и непроверенные записи остаются в реестре.

## Отметки просмотра <a id="reviews"></a>

Действующие отметки A4 в `.agents/lipi/reviews.json` переносятся общим
планом: пути, отпечатки точных адресных замен и id, с сохранением автора,
даты и объяснения. Это касается и замен внутри непереносимых файлов.
Устаревшие записи не подтверждаются заново. Повреждение реестра — C1;
невозможность доказать перенос действующей отметки — отказ до записи.
Реестр участвует в откате; [точные правила](review.md#move).

## Применение и откат <a id="apply"></a>

Перед применением проверяются все затронутые файлы; повторное чтение
для проверки неизменности не означает повторного разбора связей.
При ошибке применения или перехватываемом прерывании, включая `Ctrl+C`,
массовый перенос возвращает пути, содержимое и индекс Git к состоянию
до операции. Незатронутые изменения пользователя сохраняются и при
успешном переносе, и при откате.

Принудительное убийство процесса и отключение питания не входят в эту
гарантию. Если вернуть состояние не удалось, команда сообщает о неполном откате.

После применения просмотрите `git diff` и `git diff --cached`: переносы
индексируются, замены связей остаются в рабочем дереве. Затем выполните
`lipi check` и подготовьте к коммиту весь результат.

Код **0** — план или перенос выполнен; **2** — неверный запуск или отказ.
Код перехваченного прерывания — **130**.
