# Примеры просмотра A4

[Договор и команды](review.md). Все примеры ниже синтетические.

## Одна пара trace <a id="trace"></a>

Синтетический пример: `src/retry.py` целиком состоит из трёх строк,
каждая заканчивается LF:

```python
# @trace docs/api.md#retry
def retry_limit():
    return 3
```

Область `docs/api.md#retry` состоит ровно из следующих трёх строк с LF:

```markdown
## Повтор <a id="retry"></a>

Не более трёх попыток.
```

Предположим, вынос лимита в функцию новее описания и даёт A4. Preview:

```text
lipi review docs/api.md#retry --at src/retry.py:1 --full
```

Команда показывает A4, обе области, их координаты и отпечатки. Ключи
состояния ниже вычислены по этим строкам, а Git OID из единиц — условный
HEAD синтетического примера. Token берётся из фактического preview; он
не выводится из одного примера файла, поскольку учитывает также настройки
и прежний реестр. После чтения обеих сторон:

```text
lipi review docs/api.md#retry --at src/retry.py:1 --full --confirm <token-из-preview> --by agent:codex --reason "Лимит вынесен в функцию; число попыток и описание остались прежними."
```

Угловые скобки здесь — место под выданное значение, не буквальный аргумент.
Результат записи — 0; файл `.agents/lipi/reviews.json`:

```json
{
  "algorithm": "sha256-lines-v1",
  "entries": [
    {
      "head": "1111111111111111111111111111111111111111",
      "id": "91f5512df73f7e0e9530bced475eda5282ae99e74cd7194617acdc7671c01d53",
      "reason": "Лимит вынесен в функцию; число попыток и описание остались прежними.",
      "relation": "trace",
      "reviewed_at": "2026-11-18T12:00:00Z",
      "reviewer": "agent:codex",
      "source": {
        "kind": "trace",
        "path": "src/retry.py",
        "sha256": "75e47a6d98b5d79190a142229fc4d1dcb334736017dfad523b1418cc2b302862"
      },
      "target": {
        "anchor": "retry",
        "kind": "anchor",
        "path": "docs/api.md",
        "sha256": "213eab4bbea658e1a75bfad9183c74587cec812b2c70e6a7f679a0b646835120"
      }
    }
  ],
  "schema": 1
}
```

Повторный preview сообщает существующий id. Подтверждение нового token
возвращает `result: "unchanged"`, сохраняя дату и автора первого просмотра.
Замена `return 3` на `return 4` отменяет применимость; посторонний commit
или вставка строк перед всей областью — нет. Команда сама файл не коммитит.

## Отказ без записи <a id="refusal"></a>

У одного файла две разные группы на `docs/api.md#retry`. Выбор без строки
даёт `error: "ambiguous"`, код 2 и список обеих областей — даже если A4
пока есть лишь у одной. Повтор с `--at src/retry.py:1` уточняет выбор.
Если группы побайтно одинаковы после нормализации, строка не помогает:
сохранённое состояние не сможет различить их, поэтому уже предпросмотр
отвечает `ambiguous`, даже со строкой, и подтвердить нельзя.

Изменение области между preview и подтверждением возвращает, например:

```json
{
  "schema": 1,
  "operation": "review",
  "error": "changed-preview",
  "message": "state changed after the preview. Get a new preview"
}
```

Код 2, байты реестра прежние. Так же нельзя подтвердить T1/T2/T3,
отсутствующий A4 или выключенный код. Повреждённый JSON реестра — C1, а не пропуск
плохой записи. Ошибку нельзя обойти подтверждением другого региона.

## Управляемый перенос <a id="move"></a>

Для синтетической пары выше команда `lipi mv docs/api.md docs/http.md`
переписывает путь назначения и строку метки в `src/retry.py`. Сам кодовый
файл остаётся на месте. По общему плану source получает новый отпечаток
из-за адреса в метке; target — новый путь, но прежний отпечаток, если его
текст не менялся. Вычисляется новый id; данные автора и просмотра сохраняются.

Если при переносе страницы изменились её относительные ссылки, меняется
также отпечаток выбранной области target. Подтверждается только точная
механическая замена из плана, не любой новый текст по новому пути.
После ручного git mv запись не переводится и перестаёт совпадать.

## Уборка <a id="prune"></a>

После изменения кода старая отметка не совпадает. Для одного примера выше:

```text
lipi review --prune --format json
lipi review --prune --confirm <token-из-preview> --format json
```

Первый вызов показывает пару с причиной `changed`, второй удаляет только
показанное. Нет подтверждения — нет записи. После удаления единственной
устаревшей отметки ответ имеет вид:

```json
{"schema":1,"operation":"prune","result":"written","file":".agents/lipi/reviews.json","removed":1,"remaining":0,"unchecked":0}
```

Файл остаётся с пустым массивом entries. Неоднозначные и непроверяемые
записи команда сохраняет и перечисляет отдельно.
