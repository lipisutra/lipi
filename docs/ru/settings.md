# Настройки

Файл `lipi.json` в корне проекта. Все ключи необязательны. Чекер проверяет
ключи, типы и значения по схеме: опечатка в ключе, неверный тип или значение —
ошибка C1, проверка останавливается с кодом 2 (ей нельзя доверять). Структура
`.agents/lipi/lipi.lock`, `.agents/lipi/baseline.json` и
[`.agents/lipi/reviews.json`](review.md#state) проверяется так же,
если эти файлы есть.

Настройки, состояние и базовая линия — разные файлы: `lipi.json` пишет
только человек после первого создания, `.agents/lipi/lipi.lock` пишет `init`
(версия развёртывания и отпечатки правил и шаблона CI), а
`.agents/lipi/baseline.json` пишет `lipi baseline` (базовая линия —
зафиксированный долг проекта). `lipi review` записывает просмотренные пары
A4 в `.agents/lipi/reviews.json`. Эти файлы коммитятся. При [переносе
оформленных рабочих документов](workflow.md#upgrade) адреса в базовой
линии и действующих отметках обновляются вместе с путями документов.

| Ключ | Тип | По умолчанию | Что задаёт |
| --- | --- | --- | --- |
| `docs` | строка | `docs` | каталог описания; при ключе `languages` — каталог редакции по умолчанию и должен с ним совпадать |
| `description` | строка или `null` | нет | каталог описания системы, если оно отдельно от справки |
| `workflow` | строка или `null` | `workflow` | каталог рабочих материалов; `null` отключает его проверки, а замечание к lipi пишется в `.agents/lipi-feedback/` |
| `decisions` | непустая строка | `<workflow>/adr` | каталог решений внутри проекта, в Git без символьных ссылок в пути; явное значение заменяет стандартный каталог ADR и работает при `"workflow": null` |
| `repos` | объект | нет | явные подключения соседних репозиториев: относительный `path` и список разрешённых областей `read`; [правила подключения](#repos) |
| `enforce` | логическое | `false` | строгость проекта: `true` — pre-commit `lipi check --staged` и строгие правила агента; `false` — lipi не блокирует и не ставит хук (ADR-011) |
| `languages` | объект | нет | языковые редакции описания: `default` — редакция по умолчанию, `editions` — объект «язык: каталог», `required` — языки, в которых страница обязательна (L1) |
| `release_notes` | строка или `null` | нет | относительный путь страницы описания с записями о выпусках (обычно `CHANGELOG.md`): D3 не проверяет её размер, остальные проверки описания действуют; файла может не быть — это не ошибка, пропускать нечего |
| `limits` | объект из неотрицательных целых | 320 строк и 24 КиБ на страницу описания, 600 строк на рабочий документ, 150 на мастер-план | пределы размера: `docs_lines`, `docs_bytes`, `workflow_lines`, `masterplan_lines`; 0 отключает |
| `stale_days` | объект из целых | 30, 14 и 60 | через сколько дней аудит считает залежавшимися план, приёмку и замечание: `active`, `review`, `issue` |
| `entry` | список строк | пусто | регулярные выражения строк кода точек входа для аудита и среза |
| `layers` | объект «шаблон пути: слой» | пусто | слои карты и среза; первое совпадение задаёт слой, порядок ключей — порядок вывода; без совпадения слой — каталог верхнего уровня |
| `tests` | список строк | `test_*`, `*_test.*`, `*.test.*`, `*.spec.*`, `*Test.*` | шаблоны имён тестовых файлов в карте и срезе; список заменяет стандартные шаблоны; слой `tests` также обозначает тесты |
| `slice_budget` | целое от 1 | 60 | общий предел строк содержимого [среза](slice.md#budget); `true`, ноль и отрицательные значения недопустимы |
| `skip_dirs` | список строк | пусто | каталоги, исключённые из обхода и целей; [имя или путь](#skip-dirs) |
| `checks` | список объектов | пусто | проверки проекта, зависящие от стека (ADR-008): `name` — имя, `run` — команда списком аргументов без оболочки, `mode` — `quick` (при каждой проверке) или `audit` (только с `--audit`), `timeout` — предел времени в секундах; ошибка команды — P1 |
| `codes` | объект «код: уровень» | пусто | уровни проверок проекта (ADR-012): код → `"error"`, `"warning"` или `"off"`; без ключа действует таблица уровней чекера. Неизвестный код или уровень — C1; C1 и V1 не настраиваются |

Решения из `decisions`, например `"docs/adr"`, проверяются как решения,
даже если лежат внутри описания: шапка, ссылки и якоря; D3/D4 и проверки
языковых пар к ним не применяются. Номер берётся из имени `001-….md`,
`0001-….md` или `adr-001-….md`: все обозначают `ADR-001`. Статус задаёт
только строка `- Status: …` в шапке lipi. Без ключа и без рабочих материалов
решения по номеру недоступны. Каталог создаётся при `lipi new adr`.

Годовая раскладка PLN, ISS, DSC и AUD определяется Датой создания и не
настраивается. ADR и feedback хранятся без каталогов года.

`enforce` — единственное место, где проект выбирает строгость (ADR-011), по
умолчанию `false`. При `false` lipi не ставит pre-commit, а поставленный им
раньше `lipi init` убирает и сообщает об этом; правила агента просят
исправить ошибки своей правки или сообщить о них пользователю. С
`"enforce": true` `lipi init` ставит pre-commit
`lipi check --staged`, и ошибки не проходят до коммита. Чужой pre-commit без
метки lipi не трогает и сообщает о нём. Смену ключа применяет `lipi init`:
правила агента отрисовываются по `enforce`, поэтому до обновления V3
сообщает, что они отрисованы с другим значением. Код возврата
`lipi check` от ключа не зависит: 0 — чисто, 1 — ошибки, 2 — неверный запуск.
Значение, с которым отрисованы правила, записано в lock-файл.

`lipi init` не меняет существующий `lipi.json`. Явный аргумент, расходящийся
с настройкой, завершает команду с кодом 2 до записи и подсказывает изменить
ключ в файле. Версия развёртывания живёт только в `.agents/lipi/lipi.lock`.

`release_notes` — страница описания, которая растёт с каждым выпуском, а
не описывает текущее устройство: её размер D3 не ограничивает. Ссылки, якоря
и достижимость у такой страницы проверяются как у обычной.

## Исключение каталогов <a id="skip-dirs"></a>

`skip_dirs` без `/`, например `fixtures`, исключает каталоги с таким
именем на любой глубине. Запись с `/`, например `tests/fixtures`, исключает
только этот каталог от корня проекта и его содержимое: `src/fixtures`
и `tests/fixtures-copy` остаются. Это правило общее для описания, кода,
целей, среза, карты, аудита и переноса; у соседа используется его корень.

Разделитель пути — `/`. Повторы `/`, компоненты `.` и внутренние `..`
нормализуются: `./tests//fixtures/` равно `tests/fixtures`. Наличие `/`
до нормализации задаёт режим пути: `fixtures/` и `./fixtures` исключают
только корневой каталог. Абсолютный путь, выход выше корня и путь к самому
корню дают C1. Шаблонов glob здесь нет: символы сравниваются буквально.

## Слои карты и среза <a id="layers"></a>

Шаблоны `layers` сопоставляются с путями от корня проекта с разделителем
`/`: `*` — любое число символов, `?` — один символ, `[abc]` — один из
перечисленных. Шаблон и имя слоя — непустые строки. Первое совпадение
определяет слой; имена слоёв выводятся в порядке их первого появления в
настройке, остальные — по алфавиту. Пример:

```json
{"layers": {"tests/*": "tests", "src/api/*": "api", "src/domain/*": "domain"},
 "tests": ["test_*", "*.spec.*"], "slice_budget": 60}
```

`tests` сравнивает шаблон с именем файла. Пустой список отключает поиск по
имени; файлы слоя `tests` остаются тестами. Настройки слоёв и тестов
используют карта и срез, они не меняют состав проверок `check` и `audit`.

## Подключения репозиториев <a id="repos"></a>

```json
{"repos": {
  "core": {"path": "../core", "read": ["docs", "decisions"]},
  "client": {"path": "../client", "read": ["code", "tests"]}
}}
```

Ключи подключения — непустые имена из строчных латинских букв, цифр и
дефиса. У каждого подключения ровно два обязательных ключа:

- `path` — непустой относительный путь от корня проекта; `..` допустим,
  абсолютный путь и нулевой символ — нет;
- `read` — непустой список без повторений: `docs`, `decisions`, `code`,
  `tests`. Это разрешённые области чтения, а не зависимости программы.

Неверные типы, неизвестные поля и возможности — C1. Пути сравниваются
после разрешения символических ссылок: два имени одного корня и
подключение к самому проекту — C1. В режиме подключений имя слоя
не содержит `::`, иначе C1. Отсутствующий каталог не делает
настройку неверной: такой источник недоступен. Без ключа или при `{}`
подключений нет, поведение местного проекта сохраняется.

Источник читается только внутри объявленного корня; выход через путь или
символическую ссылку исключён. Подключённый корень внутри проекта
исключён из собственного обхода и местных целей: его читает подключение.
Отбор Git выполняется от корня каждого источника до раскрытия ссылок;
игнорируемые файлы не читаются и не служат внешними целями.
Каталоги и исключения берутся из `lipi.json`
соседа: пути `skip_dirs` считаются от его корня, не от нашего.
Архивы `history/`, `<workflow>/history/` и `<decisions>/history/` соседа
не читаются, в том числе при `docs: "."`.
Неверный или выходящий за его корень конфиг делает источник
недоступным. Без конфига доступны лишь явные цели `путь.md#якорь`.
Другая первая цифра версии в его lock-файле — недоступность; отсутствие
lock не означает несовместимость. Чужая базовая линия не читается.

Настройки `repos` соседа используются только для распознавания его ссылок
на наш физический корень; имена с двух сторон могут отличаться. Третьи
репозитории не открываются. Чужие команды `checks` не запускаются;
никаких записей, клонирования или сетевых запросов нет.

Модель источника хранит HEAD и признак незакоммиченных изменений.
У вложенного проекта HEAD и признак изменений относятся ко всему
репозиторию: правки родительского `.gitignore` тоже влияют на обход.
Неизвестные значения — `null`; отсутствие Git отличается от недоступного
каталога. Воспроизводимость требует доступной истории и чистого дерева
всех источников, включая свой проект. До первого коммита HEAD неизвестен.
Внешние `@trace` и `covers` записываются как `core::docs/api.md#request`
или `core::ADR-018`. У доступного источника неверная или запрещённая цель
даёт T1/D6, у недоступного — T4. Решение по пути с якорем тоже требует
`decisions`; внешние планы, замечания, обсуждения, аудиты и правила
исполнителя не поддерживаются. Без конфига соседа доступны только явные
цели `путь.md#якорь`; номера ADR не угадываются. Межрепозиторные T2/A4 отключены.
[Срез](slice.md#repos) по внешней цели показывает свой код; по своей —
потребителей в соседях. [Карта](map.md#repos) добавляет их слои и тесты.
Недоступность остаётся в охвате даже при `T4: off`. В графе
`check --structure` внешние ID и пути имеют префикс `имя::`, ссылки
из внешних страниц не обходятся.

## Языковые редакции <a id="languages"></a>

Несколько языков описания включаются ключом `languages`:

```json
{"docs": "docs/en",
 "languages": {"default": "en",
               "editions": {"en": "docs/en", "ru": "docs/ru"},
               "required": ["en", "ru"]}}
```

Страницы пары — один относительный путь внутри редакций (`docs/en/guide.md` и
`docs/ru/guide.md`), у каждой редакции свой `README.md`, а вложенные каталоги
редакций не допускаются. Каталог описания (`docs`) — каталог редакции по
умолчанию: задайте его равным `editions[default]`, иначе ошибка C1.
Пути `@trace` и `covers` считаются от корня проекта, включая каталог нужной
редакции. Без ключа `languages` описание — один каталог.

## Язык интерфейса <a id="interface-language"></a>

`lipi lang` показывает текущий язык. `lipi lang ru` записывает выбор в
`~/.config/lipi/config.json` для всех проектов. По умолчанию — `en`.
При неизвестном языке команда перечисляет доступные.

Настройка задаёт язык сообщений и справки в терминале. Выберите его до
первого `lipi init`, чтобы на нём были и те заготовки, которые создаст
команда, включая `AGENTS.md` и начальные страницы в `docs/` и `workflow/`.
Повторный запуск сохраняет существующие заготовки.

Управляемые правила в `.agents/lipi/` и файл GitHub Actions всегда на
английском. `lipi guide` печатает английскую инструкцию по развёртыванию.
Формат рабочих материалов, служебные поля и сообщения lipi в JSON тоже
английские. Текст проекта в JSON сохраняет свой язык. Редакции описания
настраиваются через [`languages`](#languages).

В `src/lipi/locale/<язык>/` лежат `messages.json`, `terms.json` и шаблоны
заготовок в `templates/seed/`. Если перевода нет, используется английский
исходник. Отчёт перевода в тестах показывает пропуски и изменившиеся исходники.
