# Карта разметки проекта

`lipi map` показывает, где цели описания связаны с кодом и тестами:
строки — цели, столбцы — слои кода и тесты, клетки — число мест.
Ноль означает «связей не найдено», а не «нет реализации».
За подробностями по строке переходят к [срезу](slice.md):
`lipi slice docs/rules.md#limit`.

```bash
lipi map
lipi map --format json
lipi help map
```

## Состав строк <a id="rows"></a>

В карту входят описание всех языковых редакций, решения, корневой README,
`AGENTS.md` и собственные файлы `.agents/`. Даже без меток они показывают,
какие знания ещё не связаны с кодом. Планы, замечания, обсуждения, аудиты и
прочие Markdown-файлы входят только при наличии метки на них или их якорь.
У работ и решений виден статус из шапки, в том числе у строк их якорей.
Неразмеченные указатель и мастер-план в карту не входят. Внешние строки
добавляются только по своим меткам — [правила подключений](#repos).

- Обычная страница без меток — одна строка по пути, «меток нет».
- Если метка кода или теста ведёт на якорь страницы, показываются все её
  явные однозначные якоря, включая нулевые. Строка самой страницы при этом
  не нужна: метка без якоря на обычную страницу не разрешена.
- У решения есть строка номера, например `ADR-001`, с числом меток именно
  на номер. Если размечен номер или якорь, ниже идут все якоря решения;
  иначе остаётся одна строка номера. Размеченные работы устроены так же.
- Два решения с одним номером показываются отдельно по путям, без выбора
  первого. Метка на неоднозначный номер не засчитывается.
- Обычные ссылки, `covers` и «Refines» не раскрывают страницы и не
  прибавляют мест: карта показывает только прямую разметку кода и тестов.

Группы решений идут по номеру, остальные страницы — по пути. В группе
сначала строка номера, если она есть, затем якоря в порядке строк файла.
Действуют исключения целей и обхода кода, как у среза: `skip_dirs`,
`.agents/lipi/`, архивы `history/`, `<workflow>/history/` и
`<decisions>/history/`, а также игнорируемые git файлы не попадают в карту.
Сама команда работает и без git.

## Подсчёт мест <a id="counts"></a>

Место — блок соседних отдельных строк-меток перед объявлением либо
одна строка кода с меткой, как в срезе. При подключениях его различают
репозиторий, путь и строка. Повтор цели в блоке даёт для неё одно место;
соседние строки кода с метками считаются отдельно.
Один блок с разными целями учитывается у каждой: складывать строки карты
для получения числа уникальных мест проекта нельзя.

Слои и тесты задают [настройки `layers` и `tests`](settings.md#layers).
Настроенные слои кода видны даже с нулями, в порядке настройки; остальные
встреченные слои кода — по алфавиту. Без настройки слой — каталог верхнего
уровня, у файла в корне — `.`. Тестовые места считаются только в столбце
«Тесты», независимо от слоя; слой с именем `tests` также обозначает тесты
и отдельным столбцом кода не выводится.

Считаются только разрешившиеся метки. Карта не запускает `check`, аудит,
команды из `checks`, чтение истории или `git blame`; не изменяет указатель,
базовую линию и другие файлы проекта. Ошибки меток проверяет `lipi check`,
устаревание и статус цели — `lipi slice` и `lipi audit`.

## Текст и JSON <a id="output"></a>

Заголовки и пометки в тексте следуют языку интерфейса. В JSON пояснения `note` и `notes[].text` всегда на английском; названия из проекта сохраняются.

Оба формата содержат одни строки и числа, без предела среза и обрезки.
Текст — таблица целей, названий, статусов, слоёв кода и тестов.
Названия столбцов следуют языку интерфейса.
Все нули видны. У нулевой строки страницы или номера пометка «меток нет»
относится именно к этой цели; ниже могут быть размеченные якоря.
Пустая карта явно сообщает, что подходящих целей нет.
Пояснение о смысле нуля присутствует всегда. При подключениях добавляются
[столбцы источников и охват](#repos); непрочитанное не показывается нулями.

В JSON:

| Поле | Значение |
| --- | --- |
| `schema` | `1` |
| `layers` | упорядоченный список столбцов кода, без тестов |
| `rows` | строки в порядке текстового ответа |
| `note` | пояснение: отсутствие связи не означает отсутствие реализации |

Строка содержит `target`, `title`, `kind` (`page`, `section`, `decision`
или `work`), `code` (объект «слой: число», все столбцы включая нули),
`tests` (число). `status` — значение английского поля `Status` (например, `accepted`); оно присутствует только у решения, работы и их якорей.
`target` — путь, путь с якорем или канонический номер работы.

Например, при слоях `api` и `domain` строка понятия может быть такой:

```json
{"target":"docs/rules.md#limit","title":"Предел","kind":"section",
 "code":{"api":1,"domain":0},"tests":2}
```

## Коды возврата <a id="exit"></a>

- **0** — карта получена, в том числе пустая, неполная и с T4 уровня `error`.
- **2** — неверные аргументы или настройки. Ошибки настроек имеют код C1;
  при `--format json` выводятся в формате находок чекера.

Карта не выполняет поиск одной цели, поэтому код 1 здесь не используется.

## Подключённые репозитории <a id="repos"></a>

При непустом `repos` карта дополняется источниками. Без подключений
сохраняются прежние поля и поведение.

### Строки и охват

К обычному набору своих строк добавляются только внешние
цели, на которые прямо указали метки **своего** кода или тестов. Весь каталог
описания соседа не импортируется. Прочитанная внешняя страница раскрывается
по [обычным правилам строк](#rows): якоря — в порядке файла, решение — со
строкой номера; чтение требует `docs` или `decisions` по типу цели.
Без `lipi.json` у соседа доступны лишь якоря прочитанной страницы: ни строки
номера, ни строки страницы как цели, ни обратного поиска из такого соседа.
Строки различаются парой `(repo, target)`. Сначала идут свои группы, затем
внешние — в порядке ключей `repos`; внутри источника сохраняется обычный
порядок. Обычные ссылки и `covers` по-прежнему не добавляют строк и мест.

Обратный поиск добавляет места из прямых соседей с `read: code` или `tests`,
только когда имя в их внешней метке разрешается в корень **своего** проекта.
Имена подключения с двух сторон могут различаться. Поиска через соседа в
третьих репозиториях нет; его метки на свои цели или на другие подключения
не расширяют карту. Правила исполнителя соседей не импортируются.

`code` разрешает места обычного кода, `tests` — тестовые места. При одном
`code` тесты соседа не считаются; при одном `tests` не появляются его слои
обычного кода. Классификация, слои и исключения — из настроек самого соседа.
Все числа относятся к найденному среди перечисленных и доступных источников;
этот охват явно назван в тексте и в `notes` с кодом `repos-scope`.

### Столбцы и JSON

Сохраняются `schema: 1`, `note` и смысл существующих счётчиков.
Только при непустом `repos` добавляются следующие поля:

| Поле | Значение |
| --- | --- |
| `checks.repos`, `reproducible` | [общие метаданные источников](slice.md#repos), включая свой и все объявленные подключения |
| `incomplete` | `true`, если хотя бы одно подключение недоступно |
| `notes` | массив объектов `{code, text}`: охват, недоступность и причины невоспроизводимости |
| `signals` | сигналы T4 по недоступным подключениям; без прочих проверок чекера |
| `rows[].repo` | `null` для своей цели или имя подключения — владельца цели |
| `rows[].test_counts` | упорядоченный массив `{repo, count}` для каждого читаемого источника тестов, включая нули |

`rows[].target` остаётся без префикса подключения. Исключение для имён
столбцов явное: `layers` содержит свои слои, затем `<имя>::<слой>` соседей
с `read: code`, в порядке подключений. Каждый `rows[].code` содержит все
эти столбцы, включая нулевые. Порядок слоёв внутри источника — прежний.
В режиме подключений имя слоя не содержит `::` — иначе C1. Без `repos`
допустимые имена слоёв не меняются.
`rows[].tests` — суммарное число тестовых мест из всех читаемых источников,
равное сумме `test_counts[].count`; объект `code` тестами не дополняется.
Порядок `test_counts`: свой источник, затем доступные подключения с `tests`.

Текст группирует столбцы так: свои слои и «Тесты», затем для каждого
подключения его слои и `<имя>::Тесты`, если разрешено чтение тестов,
в том числе когда в карте нет ни одной строки.
Внешняя цель отображается как `<имя>::<цель>`. Нули видны только в столбцах
прочитанных источников. Недоступное подключение целиком отсутствует среди
столбцов и `test_counts`: нули не подменяют отсутствие данных. При сбое
после частичного чтения также исключаются все его строки и места, даже
ранее прочитанные; свои строки и места сохраняются. Счётчики пересчитываются
после исключения: ответ не зависит от того, какой файл читался первым.

Для примера: своё понятие имеет одно место в слое `api` и один свой тест;
подключение `client` с `read: ["code", "tests"]` добавляет два места `ui`
и два теста. Полный JSON:

```json
{
  "schema": 1,
  "layers": ["api", "client::ui"],
  "rows": [{"repo": null, "target": "docs/rules.md#limit", "title": "Предел",
    "kind": "section", "code": {"api": 1, "client::ui": 2}, "tests": 3,
    "test_counts": [{"repo": null, "count": 1}, {"repo": "client", "count": 2}]}],
  "note": "0 means no links were found. An implementation may still exist.",
  "incomplete": false,
  "notes": [{"code": "repos-scope", "text": "Available repositories: local, client."}],
  "signals": [],
  "checks": {"repos": [
    {"repo": null, "state": "ok", "head": "1111111111111111111111111111111111111111",
     "dirty": false, "reason": null, "read": ["docs", "decisions", "code", "tests"]},
    {"repo": "client", "state": "ok", "head": "2222222222222222222222222222222222222222",
     "dirty": false, "reason": null, "read": ["code", "tests"]}
  ]},
  "reproducible": true
}
```

### Недоступность и воспроизводимость

Метаданные читаются для своего дерева и всех прямых подключений, включая
не участвующие в строках или столбцах. Карта читает HEAD и состояние рабочего
дерева, но не историю и не `blame`. Полные SHA остаются в JSON, в тексте
достаточно первых семи знаков. Общий `reproducible` истинен только при
`state: "ok"`, известном HEAD и `dirty: false` у каждого источника.
Грязное дерево, отсутствие Git или HEAD делают его ложным; прочитанные
данные остаются доступными. Сами по себе эти состояния не дают `incomplete`.
Причины перечисляются в тексте и в примечании `repos-unreproducible`.

Недоступное подключение даёт `incomplete: true`, `reproducible: false`,
примечание `repos-incomplete` и T4. Форма сигнала:
`{"repo":"client","target_repo":"client","code":"T4","level":"warning","message":"client is unavailable: connected repository directory not found. Link unchecked","target":"client"}`.
У T4 `repo`, `target_repo` и `target` называют подключение, а не документ. Уровень берётся из
своего `codes`: `error` меняет уровень сигнала, `off` убирает только сигнал.
Метаданные, неполнота и примечания от `off` не меняются. У `lipi check`
T4 уровня `error` даёт код 1, как любая ошибка.

Например, при недоступном `client` и `"T4": "off"` соответствующие поля
предыдущего ответа заменяются следующими — это **фрагмент JSON**:

```json
{
  "layers": ["api"],
  "rows": [{"repo": null, "target": "docs/rules.md#limit", "title": "Предел",
    "kind": "section", "code": {"api": 1}, "tests": 1,
    "test_counts": [{"repo": null, "count": 1}]}],
  "incomplete": true,
  "reproducible": false,
  "signals": [],
  "notes": [
    {"code": "repos-scope", "text": "Available repositories: local."},
    {"code": "repos-incomplete", "text": "client is unavailable: connected repository directory not found. Links unchecked"}
  ],
  "checks": {"repos": [
    {"repo": null, "state": "ok", "head": "1111111111111111111111111111111111111111",
     "dirty": false, "reason": null, "read": ["docs", "decisions", "code", "tests"]},
    {"repo": "client", "state": "unavailable", "head": null,
     "dirty": null, "reason": "connected repository directory not found", "read": ["code", "tests"]}
  ]}
}
```

Коды возврата: **0** для полученной карты, включая неполную
и T4 уровня `error`; **2** для неверных аргументов или настроек своего
проекта. Ошибка настроек соседа делает его недоступным. Числа в карте
содержат только прочитанные данные; чужое устаревание не вычисляется.
